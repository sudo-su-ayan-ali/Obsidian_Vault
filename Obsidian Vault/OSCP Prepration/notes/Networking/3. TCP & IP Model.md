# 3. TCP/IP Model — Detailed & In-Depth

The **TCP/IP model** is the practical networking model used to describe how devices communicate over networks, including the **Internet**.

If you are learning networking for **cybersecurity, VAPT, penetration testing, or OSCP**, you should understand TCP/IP more deeply than simply memorizing its four layers. You need to understand:

- what each layer does
    
- what protocols operate there
    
- what data looks like at each layer
    
- how encapsulation/decapsulation works
    
- how packets travel between hosts
    
- how TCP and IP are different
    
- how TCP/IP maps to OSI
    
- where common attacks occur
    

---

# 1. TCP/IP Architecture

## What is TCP/IP?

**TCP/IP** stands for:

> **Transmission Control Protocol / Internet Protocol**

It is a **protocol suite**, not just two protocols.

The TCP/IP suite contains many protocols, including:

- IP
    
- TCP
    
- UDP
    
- ICMP
    
- ARP
    
- DNS
    
- HTTP
    
- HTTPS
    
- SSH
    
- FTP
    
- SMTP
    
- DHCP
    
- TLS
    
- and many others
    

The TCP/IP model organizes these protocols into layers.

### TCP/IP has 4 main layers

|Layer|Name|Main responsibility|
|---|---|---|
|4|Application|Network applications and application protocols|
|3|Transport|End-to-end communication|
|2|Internet|Logical addressing and routing|
|1|Network Access|Local network delivery|

From top to bottom:

```text
+-----------------------------+
|      Application Layer      |
| HTTP DNS SSH SMTP DHCP ...  |
+-----------------------------+
|       Transport Layer       |
| TCP UDP                     |
+-----------------------------+
|        Internet Layer       |
| IP ICMP                     |
+-----------------------------+
|     Network Access Layer    |
| Ethernet Wi-Fi ARP ...      |
+-----------------------------+
```

The numbering is sometimes presented from bottom to top, so don't get confused. The important thing is understanding the responsibilities.

---

# 2. Why Do We Need Layers?

Imagine you open:

```text
https://example.com
```

A huge number of things must happen.

Your browser needs to:

1. create an HTTP request
    
2. resolve `example.com` to an IP address
    
3. establish a transport connection
    
4. determine the destination IP
    
5. determine how to reach the destination network
    
6. place the data into Ethernet/Wi-Fi frames
    
7. transmit electrical/radio signals
    
8. receive the response
    
9. reconstruct the data
    
10. give the response back to the browser
    

Without layers, networking would become extremely complicated.

Each layer has a specific responsibility.

For example:

```text
HTTP
 ↓
TCP
 ↓
IP
 ↓
Ethernet
 ↓
Physical transmission
```

Each protocol doesn't need to understand everything below it.

HTTP doesn't need to know how an Ethernet frame is electrically transmitted.

Similarly, Ethernet doesn't need to understand HTTP.

This is called **layered architecture**.

---

# 3. Network Access Layer

The **Network Access Layer** is the lowest layer of the TCP/IP model.

It is responsible for communication over the **local network**.

It roughly corresponds to:

- OSI Layer 1 — Physical
    
- OSI Layer 2 — Data Link
    

Therefore, TCP/IP combines OSI's Physical and Data Link layers into one layer.

---

## Main responsibilities

The Network Access Layer handles things such as:

- physical transmission
    
- framing
    
- MAC addressing
    
- local delivery
    
- media access
    
- Ethernet
    
- Wi-Fi
    
- network interface communication
    
- error detection at the link level
    

---

# 4. Ethernet

One of the most important Network Access Layer technologies is:

**Ethernet**

For example:

```text
Computer A
    |
Ethernet
    |
Switch
    |
Ethernet
    |
Computer B
```

Ethernet uses **MAC addresses** for local network communication.

Example:

```text
AA:BB:CC:11:22:33
```

A MAC address identifies a network interface at the local-link level.

---

# 5. MAC Address

A MAC address is generally a **48-bit hardware/link-layer address** used by Ethernet.

Example:

```text
00:1A:2B:3C:4D:5E
```

Compare:

```text
IP address:
192.168.1.10

MAC address:
00:1A:2B:3C:4D:5E
```

They serve different purposes.

### IP

Used for:

> Logical addressing and routing between networks.

### MAC

Used for:

> Local-link delivery.

This distinction is extremely important.

---

# 6. Ethernet Frame

At the Network Access Layer, data is carried inside a **frame**.

Simplified Ethernet frame:

```text
+------------------+
| Destination MAC  |
+------------------+
| Source MAC       |
+------------------+
| EtherType        |
+------------------+
| Payload          |
+------------------+
| FCS              |
+------------------+
```

Example:

```text
Destination MAC:
AA:AA:AA:AA:AA:AA

Source MAC:
BB:BB:BB:BB:BB:BB

Payload:
IP packet
```

Notice something important:

> An Ethernet frame can contain an IP packet.

---

# 7. Wi-Fi

Wi-Fi also operates primarily at the Network Access Layer.

For example:

```text
Laptop
   |
 Wi-Fi
   |
Access Point
   |
Router
```

Your laptop may communicate with the access point using Wi-Fi frames.

The upper layers don't fundamentally care whether the local connection is:

```text
Ethernet
```

or:

```text
Wi-Fi
```

The IP layer can operate over either.

---

# 8. ARP

**ARP = Address Resolution Protocol**

ARP is used in IPv4 networks to discover the MAC address associated with an IP address on the local network.

Suppose your machine wants to communicate with:

```text
192.168.1.20
```

but doesn't know its MAC address.

It can send an ARP request:

```text
Who has 192.168.1.20?
```

The device responds:

```text
192.168.1.20 is at
AA:BB:CC:DD:EE:FF
```

Your machine can then construct the Ethernet frame.

### Important cybersecurity relevance

ARP is important for understanding:

- ARP spoofing
    
- ARP poisoning
    
- MITM attacks
    
- local network reconnaissance
    

Example attack concept:

```text
Victim
   |
   | ARP
   ↓
Attacker
   |
   ↓
Router
```

The attacker may attempt to convince the victim that the attacker's MAC address belongs to the router.

---

# 9. Internet Layer

The second TCP/IP layer is the:

> **Internet Layer**

Its primary responsibility is:

> **Logical addressing and routing packets between networks.**

The most important protocol here is:

**IP — Internet Protocol**

---

# 10. IP

IP provides logical addressing.

There are two major versions:

```text
IPv4
IPv6
```

Example IPv4:

```text
192.168.1.10
```

Example IPv6:

```text
2001:db8::1
```

---

# 11. Why Do We Need IP?

MAC addresses are primarily useful on the local network.

But the Internet consists of many networks.

For example:

```text
Network A
192.168.1.0/24

        |
      Router
        |
        |
      Router
        |
Network B
203.0.113.0/24
```

IP allows routers to determine where packets should go.

---

# 12. IP Addressing

An IPv4 address contains:

```text
32 bits
```

Example:

```text
192.168.1.10
```

Binary:

```text
11000000.10101000.00000001.00001010
```

An IPv4 address consists of:

```text
Network portion
+
Host portion
```

The subnet mask determines the boundary.

Example:

```text
192.168.1.10/24
```

The `/24` means:

```text
24 bits = network
8 bits  = host
```

Network:

```text
192.168.1.0
```

Host:

```text
10
```

---

# 13. Routing

Routers operate primarily at the Internet Layer.

Suppose:

```text
PC A
192.168.1.10
```

wants to communicate with:

```text
Server
8.8.8.8
```

The packet may travel:

```text
PC
 ↓
Default Gateway
 ↓
Router
 ↓
ISP Router
 ↓
Internet Routers
 ↓
Destination Network
 ↓
Server
```

Each router examines the destination IP.

For example:

```text
Destination:
8.8.8.8
```

The router consults its routing table.

It determines:

> Which next hop should I use to reach 8.8.8.8?

---

# 14. IP Packet

At the Internet Layer, the PDU is generally called an:

> **IP packet**

Simplified:

```text
+----------------------+
| IP Header            |
+----------------------+
| Transport Segment    |
+----------------------+
```

The IP header contains information such as:

- source IP
    
- destination IP
    
- TTL/Hop Limit
    
- protocol/next-header information
    
- fragmentation-related fields in IPv4
    
- other control information
    

Example:

```text
Source IP:
192.168.1.10

Destination IP:
93.184.216.34
```

---

# 15. TTL

**TTL = Time To Live**

TTL prevents packets from circulating indefinitely because of routing loops.

Example:

```text
TTL = 64
```

Each router generally decrements the TTL by one.

```text
Router 1:
64 → 63

Router 2:
63 → 62

Router 3:
62 → 61
```

Eventually:

```text
TTL = 0
```

The packet is discarded.

This is also fundamental to how:

```text
traceroute
```

works.

---

# 16. ICMP

Another important Internet Layer protocol is:

> **ICMP — Internet Control Message Protocol**

It is used for network control and diagnostic messaging.

Examples include:

```text
ping
```

and:

```text
traceroute
```

For example:

```bash
ping 8.8.8.8
```

typically uses ICMP Echo Request and Echo Reply for IPv4.

---

# 17. Transport Layer

The Transport Layer provides communication between applications/processes on different hosts.

The two most important transport protocols are:

```text
TCP
UDP
```

This layer is extremely important for cybersecurity.

---

# 18. TCP

**TCP = Transmission Control Protocol**

TCP provides:

- connection-oriented communication
    
- reliable delivery
    
- ordered delivery
    
- retransmission
    
- acknowledgements
    
- flow control
    
- congestion control
    

TCP is used by many protocols, including:

```text
HTTP
HTTPS
SSH
FTP
SMTP
IMAP
```

---

# 19. UDP

**UDP = User Datagram Protocol**

UDP is simpler than TCP.

It provides:

- connectionless communication
    
- low protocol overhead
    
- no built-in reliable delivery
    
- no guaranteed ordering
    
- no TCP-style connection establishment
    

Common uses include:

```text
DNS
DHCP
VoIP
streaming
gaming
QUIC
```

---

# 20. TCP Ports

One of TCP's important functions is identifying applications using **port numbers**.

Example:

```text
192.168.1.10:51532
```

communicating with:

```text
93.184.216.34:443
```

Here:

```text
192.168.1.10
```

is the source IP.

```text
51532
```

is the source port.

```text
93.184.216.34
```

is the destination IP.

```text
443
```

is the destination port.

---

# 21. Why Do We Need Ports?

Imagine one computer is running:

```text
Web browser
SSH client
Email client
DNS resolver
```

All of these use the same IP address.

How does the operating system know which application should receive incoming data?

Ports.

Conceptually:

```text
IP address
     +
Port
     ↓
Specific communication endpoint
```

For example:

```text
192.168.1.10:443
```

identifies a TCP endpoint.

---

# 22. TCP Three-Way Handshake

Before normal TCP data transfer, TCP establishes a connection using the **three-way handshake**.

```text
Client                         Server

   SYN ------------------------>

       <------------------- SYN-ACK

   ACK ------------------------>
```

### Step 1 — SYN

Client sends:

```text
SYN
```

Meaning:

> I want to establish a TCP connection.

### Step 2 — SYN-ACK

Server responds:

```text
SYN + ACK
```

Meaning:

> I received your request and I also want to establish the connection.

### Step 3 — ACK

Client responds:

```text
ACK
```

The connection can now proceed with data transfer.

---

# 23. TCP Segment

TCP data is carried inside a:

> **TCP segment**

Simplified:

```text
+---------------------+
| TCP Header          |
+---------------------+
| Application Data    |
+---------------------+
```

TCP header includes important fields such as:

- source port
    
- destination port
    
- sequence number
    
- acknowledgement number
    
- flags
    
- window size
    
- checksum
    

Important flags include:

```text
SYN
ACK
FIN
RST
PSH
URG
```

For penetration testing, understanding these flags is very useful.

---

# 24. TCP Sequence Numbers

TCP must ensure that data arrives in the correct order.

Suppose an application sends:

```text
A B C D E
```

The network might deliver packets in a different order.

TCP uses sequence numbers to reconstruct the correct stream.

Conceptually:

```text
Segment 1 → sequence 1000
Segment 2 → sequence 1001
Segment 3 → sequence 1002
```

The receiver can use these values to determine ordering and detect missing data.

---

# 25. TCP Reliability

Suppose:

```text
Client → Server
```

sends:

```text
Packet A
Packet B
Packet C
```

but Packet B is lost.

The receiver can indicate what it has successfully received, and TCP can retransmit missing data.

Conceptually:

```text
A → received
B → lost
C → received

        ↓

TCP detects missing data

        ↓

B retransmitted
```

This is one reason TCP is called reliable.

This is an important distinction.



# 31. TCP/IP vs OSI

This is one of the most important networking comparisons.

### OSI

Has:

```text
7 layers
```

### TCP/IP

Usually represented with:

```text
4 layers
```

Comparison:

|OSI|TCP/IP|
|---|---|
|Application|Application|
|Presentation|Application|
|Session|Application|
|Transport|Transport|
|Network|Internet|
|Data Link|Network Access|
|Physical|Network Access|

Therefore:

```text
OSI                         TCP/IP

Application ───────┐
Presentation ──────┼────── Application
Session ───────────┘

Transport ───────────────── Transport

Network ─────────────────── Internet

Data Link ─────────┐
Physical ──────────┴─────── Network Access
```

---

# 32. Major Difference

The OSI model is primarily a **conceptual/reference model**.

TCP/IP is a **practical protocol suite and architectural model** that underlies modern Internet networking.

This doesn't mean OSI is useless.

OSI is extremely useful for:

- learning networking
    
- troubleshooting
    
- describing where protocols operate
    
- understanding network architecture
    
- cybersecurity analysis
    

TCP/IP is important because it describes the protocols actually used in Internet communication.

---

# 33. Protocol Mapping

Let's map common protocols.

|TCP/IP Layer|Protocols/Technologies|
|---|---|
|Application|HTTP, HTTPS, DNS, SSH, FTP, SMTP, IMAP, DHCP, SNMP, NTP|
|Transport|TCP, UDP|
|Internet|IPv4, IPv6, ICMP|
|Network Access|Ethernet, Wi-Fi, ARP|

Note that some protocols don't fit perfectly into one layer in every implementation or textbook.

For example, **ARP** is commonly associated with the link/network boundary and is often placed in the Network Access layer in the 4-layer TCP/IP model.

# 34. Encapsulation in TCP/IP

This is one of the most important concepts.

When data moves **down** the TCP/IP stack, each layer adds its own header.

This is called:

> **Encapsulation**

Suppose you send:

```text
HTTP request
```

The process is conceptually:

```text
Application

HTTP Data
    ↓

Transport

TCP Header + HTTP Data
    ↓

Internet

IP Header + TCP Header + HTTP Data
    ↓

Network Access

Ethernet Header + IP Header + TCP Header + HTTP Data + FCS
```

---

# 35. Encapsulation Diagram

```text
Application Layer
+-----------------------+
| HTTP Data             |
+-----------------------+
              ↓
Transport Layer
+--------+-----------------------+
| TCP    | HTTP Data             |
| Header |                       |
+--------+-----------------------+
              ↓
Internet Layer
+--------+--------+----------------+
| IP     | TCP    | HTTP Data      |
| Header | Header |                |
+--------+--------+----------------+
              ↓
Network Access
+----------+--------+--------+------+
| Ethernet | IP     | TCP    | Data |
| Header   | Header | Header |      |
+----------+--------+--------+------+
```


# 37. Decapsulation

At the receiving machine, the opposite occurs.

This is called:

> **Decapsulation**

Suppose the receiver gets:

```text
Ethernet Frame
```

The process is:

```text
Frame
 ↓
Remove Ethernet header/trailer
 ↓
IP Packet
 ↓
Remove IP header
 ↓
TCP Segment
 ↓
Remove TCP header
 ↓
HTTP Data
 ↓
Application
```

Diagram:

```text
Ethernet
   ↓
IP
   ↓
TCP
   ↓
HTTP
   ↓
Browser
```

# 43. What Happens at a Router?

This is particularly important.

Suppose:

```text
PC
 ↓
Router
 ↓
Internet
 ↓
Server
```

The router receives an Ethernet frame.

It removes the local Ethernet encapsulation.

It examines the IP packet.

It checks:

```text
Destination IP
```

Then consults its routing table.

It forwards the packet toward the next hop.

The packet is encapsulated in a **new link-layer frame** for the next network.

Conceptually:

```text
Network A

Ethernet Frame A
      ↓
    Router
      ↓
IP Packet
      ↓
New Ethernet Frame B
      ↓
Network B
```

---

# 44. Important: MAC Addresses Change, IP Addresses Usually Don't

This is a very important concept.

Suppose:

```text
Client IP:
192.168.1.10

Server IP:
93.184.216.34
```

As the packet crosses routers, the source and destination **IP addresses generally remain the same** for ordinary forwarding.

But the link-layer addresses change at each hop.

Example:

```text
Hop 1:

Source MAC = Client
Destination MAC = Router


Hop 2:

Source MAC = Router
Destination MAC = Next Router


Hop 3:

Source MAC = Router
Destination MAC = Next Router
```

So:

> **IP provides end-to-end logical addressing.**

while:

> **MAC provides local-link delivery.**

# 45. End-to-End Communication

This is one of the most important concepts in TCP/IP.

Suppose:

```text
Client
192.168.1.10
   |
 Router
   |
 Router
   |
 Router
   |
Server
93.184.216.34
```

The communication is logically:

```text
Client
     <---------------->
           Server
```

But physically/logically at the network layer, the packet passes through intermediate routers.

---

# 46. End-to-End vs Hop-by-Hop

### End-to-end

TCP communication is between the endpoints.

```text
Client TCP
     ↕
Server TCP
```

Intermediate routers generally don't participate in the TCP connection itself.

### Hop-by-hop

Link-layer communication happens between neighboring devices.

```text
Client ↔ Router
Router ↔ Router
Router ↔ Router
Router ↔ Server
```

Each link can have different Layer 2 technology.

---

# 47. Example

Suppose you connect to:

```text
192.168.1.100:22
```

using SSH.

Your system may create:

```text
SSH
 ↓
TCP
 ↓
IP
 ↓

```

TCP connection:

```text

      ↕

```

But Ethernet communication might be:

```text

      ↕

      ↕
```

# 48. Five-Tuple

A very important concept for networking and cybersecurity is the **5-tuple**.

A flow can be identified using:

```text
Source IP
Destination IP
Source Port
Destination Port
Protocol
```

Example:

```text
192.168.1.10
93.184.216.34
51532
443
TCP
```

This can be represented as:

```text
192.168.1.10:51532
        ↓ TCP
93.184.216.34:443
```

Firewalls, IDS/IPS systems, NAT devices, and network monitoring tools often use this information.

---

# 49. NAT and TCP/IP

NAT stands for:

> **Network Address Translation**

It is commonly used when private networks communicate with the Internet.

Example:

```text
Private machine:

192.168.1.10:51532

        ↓ NAT

Public address:

203.0.113.10:62001
```

The NAT device translates addresses and often ports.

This is why many devices in a home can share one public IPv4 address.

For example:

```bash

```

```text
Scanner
   |
   | SYN
   ↓

```


```text

```

# 53. Layer-by-Layer Troubleshooting

The layered model also makes troubleshooting easier.

Suppose a website doesn't load.

You can investigate from lower layers upward.

### Layer 1 / Network Access

Is the interface connected?

```bash
ip link
```

### Layer 2

Can you reach the local gateway?

```bash
ip neigh
```

### Layer 3

Can you reach an IP?

```bash
ping 8.8.8.8
```

### Application

Does DNS work?

```bash
dig example.com
```

Does HTTP work?

```bash
curl https://example.com
```

This gives you a structured troubleshooting methodology.

# 58. One Complete Example to Remember

If your browser accesses an HTTPS website:

```text
                    APPLICATION
                         │
                 HTTPS / HTTP
                         │
                         ▼
                    TRANSPORT
                         │
                        TCP
                    Port 443
                         │
                         ▼
                     INTERNET
                         │
                         IP
              Source → Destination
                         │
                         ▼
                 NETWORK ACCESS
                         │
               Ethernet / Wi-Fi
                         │
                         ▼
                      PHYSICAL
                         │
                    Bits/signals
```

At the sender:

```text
Data
 ↓
TCP Segment
 ↓
IP Packet
 ↓
Ethernet Frame
 ↓
Bits
```

At the receiver:

```text
Bits
 ↓
Ethernet Frame
 ↓
IP Packet
 ↓
TCP Segment
 ↓
Application Data
```

That entire process is the core of **TCP/IP networking**.

For cybersecurity, the key takeaway is that when you inspect traffic with **Wireshark/tcpdump**, perform **Nmap scans**, analyze **firewall rules**, investigate **network services**, or perform **web/API VAPT**, you are repeatedly moving between these layers and interpreting how the headers at each layer interact.
