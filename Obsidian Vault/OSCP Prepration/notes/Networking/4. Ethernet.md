# 4. Ethernet — Detailed and In-Depth

Ethernet is one of the most important technologies in computer networking. If you are learning **networking for cybersecurity, VAPT, penetration testing, or OSCP**, you should understand Ethernet at both the **Frame level** and the **Switching level**.

Ethernet primarily operates at **OSI Layer 2 (Data Link)**, although Ethernet networks also interact closely with Layer 1 (Physical).

A simplified path looks like:

```text
Application
    ↓
Transport
    ↓
IP / Network Layer
    ↓
Ethernet / Data Link Layer
    ↓
Physical Medium
    ↓
Copper / Fiber
```

---

# 1. Ethernet Fundamentals

## What is Ethernet?

**Ethernet** is a family of networking technologies used to connect devices over a local network.

It defines things such as:

- How devices communicate over a physical medium
    
- How data is organized into frames
    
- MAC addressing
    
- Ethernet frame format
    
- How switches forward frames
    
- Link speeds
    
- Duplex operation
    
- Physical signaling
    
- Error detection
    

For example:

```text
PC A ─────── Switch ─────── PC B
```

PC A and PC B may communicate using Ethernet.

When PC A sends an IP packet to PC B, the packet is encapsulated inside an Ethernet frame.

```text
Ethernet Frame
┌──────────────┬──────────────┬──────────┬─────────┬─────┐
│ Destination  │ Source       │ EtherType│ Payload │ FCS │
│ MAC          │ MAC          │          │         │     │
└──────────────┴──────────────┴──────────┴─────────┴─────┘
```

---

# 2. Why Ethernet Is Important

Ethernet is extremely common in:

- Home networks
    
- Enterprise networks
    
- Data centers
    
- University networks
    
- Cloud infrastructure
    
- Industrial networks
    
- Servers
    
- Network appliances
    

For cybersecurity, Ethernet is important because many attacks and techniques operate around Layer 2.

Examples include:

- ARP spoofing
    
- ARP poisoning
    
- MAC spoofing
    
- MAC flooding
    
- VLAN attacks
    
- DHCP attacks
    
- Network sniffing
    
- Layer-2 reconnaissance
    
- Switch security attacks
    

Understanding Ethernet makes these attacks much easier to understand.

# 3. IEEE 802.3

Ethernet is standardized primarily through the **IEEE 802.3** family of standards.

IEEE = **Institute of Electrical and Electronics Engineers**

The 802 family contains networking standards.

For example:

```text
IEEE 802

├── 802.3 → Ethernet
│
├── 802.11 → Wi-Fi
│
├── 802.1 → Bridging, VLANs, etc.
│
└── ...
```

IEEE 802.3 covers Ethernet technologies including:

- Physical-layer specifications
    
- Ethernet MAC
    
- Frame formats
    
- Media types
    
- Speeds
    
- Duplex operation
    
- Auto-negotiation
    
- Various physical technologies
    

Examples of Ethernet technologies include:

```text
10BASE-T
100BASE-TX
1000BASE-T
10GBASE-T
```

# 4. Ethernet and OSI Layers

Ethernet primarily belongs to:

```text
OSI Layer 2
Data Link
```

But Ethernet also has a physical component.

A simplified view:

```text
Layer 2
┌─────────────────────────┐
│ Ethernet MAC            │
│ Ethernet Frame          │
│ MAC Address             │
└─────────────────────────┘

Layer 1
┌─────────────────────────┐
│ Physical Ethernet       │
│ Copper/Fiber            │
│ Electrical/Optical      │
│ Signaling               │
└─────────────────────────┘
```

This distinction is important.

### Layer 2

Deals with:

- MAC addresses
    
- Frames
    
- Switching
    
- FCS
    
- Ethernet MAC
    

### Layer 1

Deals with:

- Electrical signals
    
- Optical signals
    
- Cables
    
- Connectors
    
- Signaling
    
- Bit transmission

# 5. Ethernet Frame

The Ethernet frame is the fundamental Layer-2 data unit.

A simplified Ethernet II frame is:

```text
┌───────────────────────┐
│ Destination MAC       │ 6 bytes
├───────────────────────┤
│ Source MAC            │ 6 bytes
├───────────────────────┤
│ EtherType             │ 2 bytes
├───────────────────────┤
│ Payload               │ 46–1500 bytes normally
├───────────────────────┤
│ FCS                   │ 4 bytes
└───────────────────────┘
```

There are also physical-layer fields such as the **preamble** and **Start Frame Delimiter (SFD)** transmitted before the MAC frame.

Conceptually:

```text
Preamble | SFD | Ethernet Frame
                  │
                  ├── Destination MAC
                  ├── Source MAC
                  ├── EtherType
                  ├── Payload
                  └── FCS
```

---

# 6. Ethernet Frame Fields

Let's examine each field.

---

# 7. Destination MAC Address

The destination MAC identifies the Layer-2 recipient.

It is:

```text
6 bytes
48 bits
```

Example:

```text
00:11:22:33:44:55
```

or:

```text
00-11-22-33-44-55
```

Suppose:

```text
PC A
MAC = AA:AA:AA:AA:AA:AA

PC B
MAC = BB:BB:BB:BB:BB:BB
```

PC A wants to send an Ethernet frame to PC B.

The frame might contain:

```text
Destination:
BB:BB:BB:BB:BB:BB

Source:
AA:AA:AA:AA:AA:AA
```

---

# 8. Source MAC Address

The source MAC identifies the device/interface that transmitted the frame onto the Ethernet network.

Example:

```text
Source MAC:
AA:BB:CC:DD:EE:FF
```

The source and destination MAC addresses are independent of IP addresses.

For example:

```text
IP addresses:

192.168.1.10 → 192.168.1.20

MAC addresses:

AA:AA:AA:AA:AA:AA
        ↓
BB:BB:BB:BB:BB:BB
```

The IP addresses belong to Layer 3.

The MAC addresses belong to Layer 2.

---

# 9. MAC Address Structure

A MAC address is normally 48 bits:

```text
48 bits
↓
6 bytes
↓
12 hexadecimal digits
```

Example:

```text
00:1A:2B:3C:4D:5E
```

Conceptually:

```text
00 1A 2B 3C 4D 5E
│        │
│        └── Device/interface portion
│
└── OUI-related portion
```

Historically, the first 24 bits identify an organizationally assigned prefix, commonly called the **OUI (Organizationally Unique Identifier)**.

However, modern networking also supports locally administered addresses and virtual/randomized MAC addresses, so you should not assume every MAC maps neatly to a physical manufacturer.

---

# 10. Unicast MAC Address

A unicast MAC identifies one destination interface.

Example:

```text
AA:BB:CC:DD:EE:FF
```

A switch can forward a unicast Ethernet frame toward a particular switch port.

---

# 11. Broadcast MAC Address

The Ethernet broadcast address is:

```text
FF:FF:FF:FF:FF:FF
```

It means:

> Send this Layer-2 frame to all devices on the local broadcast domain.

Example:

```text
PC
 │
 ▼
Switch
 ├── PC 1
 ├── PC 2
 ├── PC 3
 └── PC 4
```

A broadcast frame can be delivered to all appropriate ports in the same Layer-2 broadcast domain.

ARP is a classic example of a protocol that uses Ethernet broadcast for IPv4 address resolution.

---

# 12. Multicast MAC

Multicast allows traffic to be associated with a group rather than a single destination.

For example:

```text
Sender
   │
   ▼
Switch
 ├── Host A
 ├── Host B
 └── Host C
```

Only hosts participating in the relevant multicast group should normally process the multicast traffic.

Multicast MAC addresses have specific addressing rules.

---

# 13. EtherType

The **EtherType** field identifies the protocol carried inside the Ethernet payload.

It is:

```text
2 bytes
16 bits
```

Common values include:

|EtherType|Protocol|
|---|---|
|`0x0800`|IPv4|
|`0x0806`|ARP|
|`0x86DD`|IPv6|
|`0x8100`|IEEE 802.1Q VLAN-tagged frame|

For example:

```text
EtherType = 0x0800
```

means:

```text
Payload contains IPv4
```

Therefore:

```text
Ethernet
   ↓
IPv4
   ↓
TCP
   ↓
HTTP
```

---

# 14. EtherType vs Length

Ethernet has historical formats where the field following the source MAC could represent either a **length** or an **EtherType**, depending on its value and framing format.

In modern Ethernet II networks, values commonly used as EtherTypes identify the encapsulated protocol.

For practical networking and security work, you will most often encounter Ethernet II frames.

---

# 15. Payload

The payload is the data carried by the Ethernet frame.

For example:

```text
Ethernet
    │
    └── IPv4 packet
          │
          └── TCP segment
                │
                └── Application data
```

So the Ethernet payload could contain an entire IP packet.

Example:

```text
┌──────────────────────────────┐
│ Ethernet Header              │
├──────────────────────────────┤
│ IPv4 Header                  │
├──────────────────────────────┤
│ TCP Header                   │
├──────────────────────────────┤
│ HTTP Data                    │
├──────────────────────────────┤
│ FCS                          │
└──────────────────────────────┘
```

This is encapsulation.

---

# 16. Minimum Ethernet Payload

Traditional Ethernet requires a minimum frame size.

The payload is normally at least:

```text
46 bytes
```

If the actual upper-layer data is smaller, Ethernet uses **padding**.

For example, suppose the payload is only:

```text
20 bytes
```

Ethernet can add:

```text
26 bytes padding
```

so the payload area reaches the minimum required size.

---

# 17. FCS — Frame Check Sequence

FCS stands for:

**Frame Check Sequence**

It is:

```text
4 bytes
32 bits
```

It is used for detecting transmission errors.

Ethernet uses a CRC-based mechanism, commonly referred to as **CRC-32**, to calculate the FCS.

Conceptually:

```text
Sender
   │
   ├── Calculate CRC
   │
   └── Put result into FCS
             ↓
           Network
             ↓
          Receiver
             │
             ├── Calculate CRC again
             │
             └── Compare
```

If the calculated value doesn't match, the frame is considered corrupted.

---

# 18. What FCS Does NOT Do

FCS provides **error detection**, not encryption.

It does not:

- Encrypt data
    
- Authenticate the sender
    
- Prevent modification by an attacker
    
- Guarantee delivery
    
- Correct the corrupted frame
    

For example:

```text
Original frame
      ↓
Transmission
      ↓
Corrupted frame
      ↓
FCS mismatch
      ↓
Frame rejected
```

Higher-level protocols may handle retransmission.

For example:

```text
Ethernet
    ↓
TCP
```

TCP can retransmit lost data, but that is a transport-layer mechanism, not an Ethernet FCS mechanism.

---

# 19. Ethernet Frame Size

Traditional Ethernet has a maximum frame size of approximately:

```text
1518 bytes
```

This includes:

```text
Destination MAC   6
Source MAC        6
EtherType         2
Payload           1500
FCS               4
--------------------
Total             1518
```

This corresponds to the common:

```text
MTU = 1500 bytes
```

Important distinction:

**MTU and maximum Ethernet frame size are not the same thing.**

---

# 20. MTU

MTU means:

**Maximum Transmission Unit**

For standard Ethernet:

```text
MTU = 1500 bytes
```

The MTU describes the maximum size of the Layer-3 packet that can normally be carried without fragmentation at that interface/link.

For IPv4:

```text
Ethernet MTU
     ↓
1500 bytes
     ↓
IPv4 packet
```

The Ethernet header and FCS are not counted as part of the IP MTU.

---

# 21. MTU Example

Suppose an IPv4 packet is:

```text
1500 bytes
```

Ethernet can carry it as its payload.

The Ethernet frame becomes approximately:

```text
14-byte Ethernet header
+
1500-byte IP packet
+
4-byte FCS
=
1518 bytes
```

Ignoring physical-layer preamble/SFD and inter-frame gap.

---

# 22. What If IP Packet Is Larger Than MTU?

Suppose:

```text
MTU = 1500
```

but an IPv4 packet is:

```text
4000 bytes
```

The packet cannot fit into one Ethernet frame.

IPv4 may fragment it, depending on the packet and path conditions.

IPv6 routers do not fragment packets in transit; IPv6 relies on mechanisms such as Path MTU Discovery and source-side fragmentation when needed.

This becomes important when studying:

- Network troubleshooting
    
- TCP/IP
    
- VPNs
    
- Tunneling
    
- Firewalls
    
- Path MTU Discovery
    
- ICMP
    
- IPv4 fragmentation
    
- IPv6
    

---

# 23. Jumbo Frames

A **jumbo frame** is an Ethernet frame larger than the traditional Ethernet maximum frame size.

A commonly used jumbo-frame configuration is:

```text
MTU ≈ 9000 bytes
```

But "jumbo frame" is not one universal exact size; implementations can support different maximum sizes.

Example:

```text
Normal:

MTU = 1500


Jumbo:

MTU = 9000
```

---

# 24. Why Use Jumbo Frames?

Larger frames can reduce protocol overhead for large data transfers.

Consider:

```text
Large file
    ↓
Many 1500-byte packets
```

versus:

```text
Large file
    ↓
Fewer 9000-byte packets
```

Potential benefits:

- Fewer packets
    
- Fewer packet headers
    
- Lower per-packet processing overhead
    
- Potentially better throughput for suitable workloads
    

They are particularly common in some:

- Data centers
    
- Storage networks
    
- High-performance computing environments
    
- Virtualization environments
    

---

# 25. Problems With Jumbo Frames

All relevant links/interfaces need compatible MTU handling.

For example:

```text
Server
MTU 9000
   │
Switch
MTU 1500
   │
Server
MTU 9000
```

This can create connectivity or performance problems depending on the traffic and path.

MTU mismatches can cause:

- Packet drops
    
- Fragmentation-related behavior
    
- PMTUD problems
    
- Application timeouts
    
- Difficult-to-diagnose connectivity issues

# 28. Full Duplex

**Full duplex** means a device can transmit and receive simultaneously.

Example:

```text
PC A                         Switch
  │                            │
  │────── TX ────────────────→│
  │←────── RX ────────────────│
```

Both directions can operate simultaneously.

Modern switched Ethernet is predominantly full duplex.

---

# 29. Why Full Duplex Matters

Suppose a link operates at:

```text
1 Gbps full duplex
```

The interface can theoretically transmit at:

```text
1 Gbps
```

and receive at:

```text
1 Gbps
```

simultaneously.

Therefore, the aggregate bidirectional capacity can be thought of as:

```text
1 Gbps TX + 1 Gbps RX
```

although this does **not** mean a single one-way flow gets 2 Gbps.

---

# 30. Half Duplex

Half duplex means communication can occur in both directions, but not simultaneously.

Example:

```text
Device A ─────── Medium ─────── Device B

A → B
or
B → A

but not both at the same time
```

Historically, shared Ethernet networks using hubs could operate in half-duplex mode.

---

# 31. CSMA/CD

Half-duplex Ethernet historically used:

**CSMA/CD**

Carrier Sense Multiple Access with Collision Detection.

The basic idea:

```text
Listen
  ↓
Is medium free?
  ↓
Yes
  ↓
Transmit
  ↓
Collision?
  ↓
Yes → stop → backoff → retry
```

Multiple devices could share the same collision domain.

---

# 32. Why CSMA/CD Is Mostly Historical Today

Modern switched Ethernet normally uses:

```text
Point-to-point link
+
Full duplex
```

Therefore:

```text
No shared collision domain
        ↓
No Ethernet collisions
        ↓
CSMA/CD isn't needed
```

You should still understand CSMA/CD because it explains older Ethernet behavior and networking fundamentals.

---

# 33. Collision Domain

A **collision domain** is a network segment in which devices can potentially interfere with each other's transmissions under shared-medium Ethernet.

With a hub:

```text
        Hub
      /  |  \
    PC1 PC2 PC3
```

All devices share the same collision domain.

With a switch:

```text
PC1 ──┐
      │
PC2 ──Switch── PC3
      │
PC4 ──┘
```

Each switch port generally forms its own collision domain when operating full duplex.

---

# 34. Auto-Negotiation

Ethernet interfaces can use **auto-negotiation** to determine compatible link parameters.

For example:

```text
Device A
1 Gbps
Full Duplex
     ↕
Device B
1 Gbps
Full Duplex
```

They negotiate compatible settings.

Auto-negotiation can determine things such as:

- Speed
    
- Duplex capability
    
- Other link capabilities depending on the Ethernet standard
    

---

# 35. Auto-Negotiation Example

Suppose:

```text
PC NIC:

10 Mbps
100 Mbps
1000 Mbps

Switch:

10 Mbps
100 Mbps
1000 Mbps
```

The devices negotiate a compatible mode, potentially:

```text
1000 Mbps Full Duplex
```

assuming the physical medium and hardware support it.

---

# 36. Duplex Mismatch

One important networking problem is a **duplex mismatch**.

For example:

```text
PC:
100 Mbps Full Duplex

Switch:
100 Mbps Half Duplex
```

This can result in:

- Poor performance
    
- Packet loss
    
- Retransmissions
    
- Errors
    
- Collisions on the half-duplex side
    
- Significant throughput degradation
    

A duplex mismatch is a classic Ethernet troubleshooting issue.

---

# 37. Ethernet Switching

Now we reach one of the most important concepts.

A **switch** forwards Ethernet frames between ports based primarily on MAC addresses.

Example:

```text
             Switch
          ┌───────────┐
          │           │
        PC A         PC B
```

Suppose:

```text
PC A
MAC = AA:AA:AA:AA:AA:AA

PC B
MAC = BB:BB:BB:BB:BB:BB
```

PC A sends a frame:

```text
Destination:
BB:BB:BB:BB:BB:BB

Source:
AA:AA:AA:AA:AA:AA
```

The switch examines the destination MAC.

---

# 38. MAC Address Table

The switch maintains a table commonly called a:

**MAC address table**

Example:

|MAC Address|Port|
|---|---|
|AA:AA:AA:AA:AA:AA|Port 1|
|BB:BB:BB:BB:BB:BB|Port 2|
|CC:CC:CC:CC:CC:CC|Port 3|

The switch uses this information to decide where to forward frames.

---

# 39. MAC Learning

Switches learn MAC addresses from the **source MAC address** of incoming frames.

Example:

```text
PC A
MAC AA:AA:AA:AA:AA:AA
       │
       ▼
    Port 1
       │
       ▼
     Switch
```

The switch receives the frame and learns:

```text
AA:AA:AA:AA:AA:AA → Port 1
```

Then:

```text
PC B
MAC BB:BB:BB:BB:BB:BB
```

sends a frame through Port 2.

The switch learns:

```text
BB:BB:BB:BB:BB:BB → Port 2
```

Now it has:

```text
MAC Table

AA:AA:AA:AA:AA:AA → Port 1
BB:BB:BB:BB:BB:BB → Port 2
```

---

# 40. Known Unicast Forwarding

Suppose the switch knows:

```text
BB:BB:BB:BB:BB:BB → Port 2
```

PC A sends:

```text
Destination:
BB:BB:BB:BB:BB:BB
```

The switch forwards the frame only toward Port 2.

```text
PC A
 │
 ▼
Switch
 │
 └────────→ PC B
```

It does not normally send the frame out every port.

This is one of the major differences between a switch and an old shared Ethernet hub.

---

# 41. Unknown Unicast

Suppose the switch doesn't know where the destination MAC is.

Example:

```text
Destination:
DD:DD:DD:DD:DD:DD
```

but the MAC table contains no entry for it.

The switch may **flood** the frame out the relevant ports, except the port on which the frame arrived, subject to VLAN and switch behavior.

```text
             Switch
           /    |    \
         PC1   PC2   PC3
               ↑
        Unknown destination
```

This is called **unknown-unicast flooding**.

Once the destination device responds, the switch can learn its source MAC and update the table.

---

# 42. Broadcast Forwarding

Suppose a frame has:

```text
Destination:
FF:FF:FF:FF:FF:FF
```

The switch treats it as a broadcast and forwards it to appropriate ports in the same broadcast domain, except the incoming port.

Example:

```text
             Switch
          /    |    \
        PC1   PC2   PC3
               ↑
        Broadcast
```

PC2 and PC3 receive it.

---

# 43. Switch vs Hub

This is extremely important.

### Hub

A hub essentially repeats signals/frames to other ports.

```text
PC1
 │
 ├── Hub ── PC2
 │
 └──────── PC3
```

Traffic is visible to devices sharing the medium.

### Switch

A switch intelligently forwards frames based on MAC addresses.

```text
PC1
 │
 └── Switch ── PC2
```

If the destination is known, the frame can be forwarded only toward the relevant port.

---

# 44. Ethernet Switching Process

A simplified switch forwarding process:

```text
Frame arrives
      ↓
Read source MAC
      ↓
Learn/update source MAC → incoming port
      ↓
Read destination MAC
      ↓
Is destination known?
      │
   ┌──┴───┐
  YES     NO
   │       │
   ↓       ↓
Forward   Flood
specific  appropriate
port      ports
```

For broadcasts:

```text
Broadcast
    ↓
Flood within broadcast domain
```

---

# 45. Example: Complete Ethernet Communication

Suppose:

```text
PC A
IP: 192.168.1.10
MAC: AA:AA:AA:AA:AA:AA

PC B
IP: 192.168.1.20
MAC: BB:BB:BB:BB:BB:BB
```

PC A wants to send data to PC B.

### Step 1 — Application

For example:

```text
HTTP request
```

### Step 2 — TCP

TCP adds a TCP header.

```text
TCP
+
HTTP data
```

### Step 3 — IP

IPv4 adds an IP header.

```text
IPv4
+
TCP
+
HTTP
```

### Step 4 — Ethernet

Ethernet adds:

```text
Destination MAC = BB:BB:BB:BB:BB:BB
Source MAC      = AA:AA:AA:AA:AA:AA
EtherType       = 0x0800
```

Then:

```text
Ethernet
    ↓
IPv4
    ↓
TCP
    ↓
HTTP
```

### Step 5 — Switch

The switch reads:

```text
Destination MAC
```

and checks its MAC table.

### Step 6 — Forward

If:

```text
BB:BB:BB:BB:BB:BB → Port 2
```

then:

```text
PC A
 │
 ▼
Switch
 │
 └────────→ Port 2 → PC B
```

### Step 7 — PC B

PC B removes the Ethernet header/trailer and passes the IP packet upward.

```text
Ethernet
   ↓
IPv4
   ↓
TCP
   ↓
HTTP
```

This is **decapsulation**.

---

# 46. Ethernet and ARP

Ethernet and ARP are closely related in IPv4 networks.

Suppose PC A knows:

```text
Destination IP:
192.168.1.20
```

but doesn't know:

```text
Destination MAC
```

It can use ARP.

PC A sends an ARP request as an Ethernet broadcast:

```text
Destination MAC:
FF:FF:FF:FF:FF:FF
```

Conceptually:

```text
"Who has 192.168.1.20?"
```

PC B responds:

```text
192.168.1.20 is at BB:BB:BB:BB:BB:BB
```

PC A can then send the actual Ethernet frame to:

```text
BB:BB:BB:BB:BB:BB
```

This is foundational for understanding **ARP spoofing/poisoning**.

---

# 47. Ethernet and Routers

A router separates Layer-2 networks.

Example:

```text
LAN 1
192.168.1.0/24
      │
      ▼
   Router
      │
      ▼
LAN 2
192.168.2.0/24
```

Ethernet frames do **not normally travel unchanged through a router**.

The router:

1. Receives an Ethernet frame.
    
2. Removes the Ethernet encapsulation.
    
3. Examines the IP packet.
    
4. Makes a Layer-3 routing decision.
    
5. Builds a new Layer-2 frame on the outgoing interface.
    

Conceptually:

```text
LAN 1

Ethernet A
    ↓
IPv4
    ↓
Router
    ↓
IPv4
    ↓
Ethernet B

LAN 2
```

The IP packet may continue while the Layer-2 framing changes.

---

# 48. Ethernet MAC vs IP Address

This distinction is fundamental.

|MAC|IP|
|---|---|
|Layer 2|Layer 3|
|Hardware/interface-oriented identifier|Logical network address|
|Used by switches|Used by routers|
|Ethernet frame|IP packet|
|Local network delivery|Inter-network routing|

Example:

```text
MAC:
AA:BB:CC:DD:EE:FF

IP:
192.168.1.10
```

A device can change its IP address without necessarily changing its physical NIC MAC address.

Likewise, modern systems can use virtual or locally administered MAC addresses.

---

# 49. Ethernet Broadcast Domain

A broadcast domain is the set of devices that receive a Layer-2 broadcast within the relevant network segment/VLAN.

Example:

```text
          Switch
      /     |     \
    PC1    PC2    PC3

Broadcast
   ↓
PC1 + PC2 + PC3
```

Routers generally separate broadcast domains.

VLANs can also divide a physical switch infrastructure into separate Layer-2 broadcast domains.

This becomes extremely important in enterprise networking.

---

# 50. Ethernet and VLANs

Although VLANs are a separate topic, understand the relationship.

Without VLAN segmentation:

```text
Switch
├── PC1
├── PC2
├── PC3
└── PC4

One broadcast domain
```

With VLANs:

```text
Switch

VLAN 10
├── PC1
└── PC2

VLAN 20
├── PC3
└── PC4
```

The same physical switch can provide multiple logical Layer-2 networks.

802.1Q VLAN tagging adds a VLAN-related field to Ethernet frames.

# 51. Ethernet Frame With VLAN Tag

A simplified tagged Ethernet frame:

```text
┌──────────────┬──────────────┬──────────┬──────────┬─────────┬─────┐
│ Destination  │ Source       │ 802.1Q   │ EtherType│ Payload │ FCS │
│ MAC          │ MAC          │ Tag      │          │         │     │
└──────────────┴──────────────┴──────────┴──────────┴─────────┴─────┘
```

The 802.1Q tag includes VLAN information.

This is important for:

- VLAN segmentation
    
- Trunk links
    
- VLAN hopping concepts
    
- Network architecture
    
- Switch configuration

# 52. Ethernet Security Relevance

For cybersecurity, Ethernet is not merely theoretical.

Understanding Ethernet helps explain:

### ARP spoofing

```text
Attacker
   ↓
False ARP information
   ↓
Victim traffic
```

### MAC spoofing

An attacker changes the MAC address presented by an interface.

### MAC flooding

An attacker attempts to overwhelm a switch's MAC address table, potentially causing abnormal flooding behavior.

### VLAN attacks

Misconfigurations involving VLANs and trunks can create Layer-2 security problems.

### Packet sniffing

Tools such as Wireshark can capture and inspect Ethernet frames.

For example:

```text
Ethernet II
    ↓
Destination MAC
Source MAC
EtherType
    ↓
IPv4
    ↓
TCP
    ↓
Application protocol
```

# 54. Important Ethernet Numbers to Memorize

For networking and cybersecurity interviews, these are useful:

|Item|Value|
|---|--:|
|MAC address|48 bits / 6 bytes|
|Ethernet destination MAC|6 bytes|
|Ethernet source MAC|6 bytes|
|EtherType|2 bytes|
|FCS|4 bytes|
|Standard Ethernet MTU|1500 bytes|
|Typical Ethernet II frame size|64–1518 bytes|
|Minimum Ethernet frame size|64 bytes|
|Broadcast MAC|FF:FF:FF:FF:FF:FF|
|IPv4 EtherType|0x0800|
|ARP EtherType|0x0806|
|IPv6 EtherType|0x86DD|
|802.1Q VLAN EtherType|0x8100|

The 64-byte minimum and 1518-byte maximum refer to the Ethernet frame including the MAC header and FCS, excluding the physical-layer preamble/SFD.

Put everything together:

```text
                  APPLICATION
                       │
                       ▼
                    TCP/UDP
                       │
                       ▼
                      IP
                       │
                       ▼
              ┌─────────────────┐
              │    Ethernet     │
              │                 │
              │ Destination MAC │
              │ Source MAC      │

                    Switch
                       │
          ┌────────────┼────────────┐
```

The switch primarily cares about:

```text
Destination MAC
```

while learning:

```text
Source MAC → Incoming Port
```

# 56. The Most Important Conceptual Distinction

You should be able to answer this immediately:

### IP address

Answers:

> **Which Layer-3 destination/network am I trying to reach?**

### MAC address

Answers:

> **Which Layer-2 interface should receive this frame on the local Ethernet network?**

### Switch

Answers:

> **Which port should this Ethernet frame go out?**

### Router

Answers:

> **Which Layer-3 path/interface should this IP packet take next?**

This distinction is fundamental to networking.

# 57. Ethernet Encapsulation

A real communication stack might look like:

```text
HTTP Request
      ↓
TCP Segment
      ↓
IP Packet
      ↓
Ethernet Frame
      ↓
Bits/signals
```

At the receiving side:

```text
Bits/signals
      ↓
Ethernet Frame
      ↓
IP Packet
      ↓
TCP Segment
      ↓
HTTP Request
```

So Ethernet is the **Layer-2 container** that carries Layer-3 packets across an Ethernet link.

# 58. Ethernet in Your Cybersecurity Learning Path

Since you're studying networking for cybersecurity, I'd learn Ethernet in this order:

```text
1. MAC addresses
        ↓
2. Ethernet frame
        ↓
3. EtherType
        ↓
4. MTU
        ↓
5. Switches
        ↓
6. MAC address tables
        ↓
7. Broadcast / multicast / unicast
        ↓
8. ARP
        ↓
9. VLANs
        ↓
10. Trunking
        ↓
11. STP
        ↓
12. ARP spoofing
        ↓
13. MAC spoofing
        ↓
14. VLAN attacks
        ↓
15. Packet analysis with Wireshark
```

Once you understand this chain, Ethernet stops being a collection of definitions and becomes a complete system:

```text
                  ETHERNET
                      │
        ┌─────────────┴─────────────┐
        │                           │
    Layer 2                     Layer 1
        │                           │
 ┌──────┴──────┐             ┌─────┴─────┐
 │             │             │           │
Frames       MAC           Copper      Fiber
 │
 ├── Destination MAC
 ├── Source MAC
 ├── EtherType
 ├── Payload
 └── FCS
        │
        ▼
      SWITCH
        │
        ├── MAC Learning
        ├── Forwarding
        ├── Flooding
        └── Filtering
        │
        ▼
   Local Network
        │
        ├── ARP
        ├── VLAN
        ├── Broadcast
        └── Unicast
```

**The key idea:** Ethernet provides the **local Layer-2 delivery mechanism**, MAC addresses identify Layer-2 interfaces, Ethernet frames carry Layer-3 packets, and switches use MAC-address learning to forward those frames efficiently.
