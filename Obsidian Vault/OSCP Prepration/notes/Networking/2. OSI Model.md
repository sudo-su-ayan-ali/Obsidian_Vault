# 2. OSI Model — Detailed & In-Depth

The **OSI (Open Systems Interconnection) model** is a conceptual framework used to understand how data moves between computers over a network.

It divides network communication into **7 logical layers**. Each layer has a specific responsibility and communicates with the layer immediately above and below it.

For cybersecurity, networking, troubleshooting, packet analysis, penetration testing, and protocol analysis, you should understand **what each layer does, what protocols/devices operate there, what attacks occur there, and how to troubleshoot it**.

---

# 1. OSI Model Overview

The seven OSI layers are:

|Layer|Name|Main Responsibility|Common Examples|
|---|---|---|---|
|7|Application|Network services for applications|HTTP, DNS, SMTP, FTP|
|6|Presentation|Data format, encryption, compression|TLS, JPEG, JSON, UTF-8|
|5|Session|Establish/manage sessions|RPC, session management|
|4|Transport|End-to-end delivery|TCP, UDP|
|3|Network|Logical addressing & routing|IP, ICMP, routers|
|2|Data Link|Frames, MAC addressing|Ethernet, Wi-Fi, switches|
|1|Physical|Raw electrical/radio/optical signals|Cables, fiber, radio|

The easiest way to remember the order:

> **A P S T N D P**

**A**ll  
**P**eople  
**S**eem  
**T**o  
**N**eed  
**D**ata  
**P**rocessing

From bottom to top:

> **Physical → Data Link → Network → Transport → Session → Presentation → Application**

---

# 2. Why Was the OSI Model Created?

Before standardized networking models, different vendors could implement networking differently.

The OSI model provides a common conceptual framework.

For example, when you open:

```text
https://example.com
```

many things happen:

```text
Application
    ↓
Presentation
    ↓
Session
    ↓
Transport
    ↓
Network
    ↓
Data Link
    ↓
Physical
```

The receiving computer processes the information in the opposite direction:

```text
Physical
    ↓
Data Link
    ↓
Network
    ↓
Transport
    ↓
Session
    ↓
Presentation
    ↓
Application
```

This is called:

- **Encapsulation** → sender side
    
- **Decapsulation** → receiver side
    

---

# 3. Layer 1 — Physical Layer

## Purpose

The Physical layer is responsible for transmitting **raw bits** over a physical medium.

It doesn't understand:

- IP addresses
    
- MAC addresses
    
- TCP
    
- HTTP
    
- DNS
    
- usernames
    
- files
    

It deals with physical transmission.

A bit is ultimately represented through physical signals.

For example:

```text
10110100
```

could be represented using:

- electrical voltage
    
- light pulses
    
- radio waves
    

depending on the medium.

---

## Physical Media

### Copper

Examples:

```text
Cat5e
Cat6
Cat6a
```

Electrical signals travel through copper.

### Fiber

Uses light.

Types include:

- Single-mode fiber
    
- Multimode fiber
    

### Wireless

Uses radio frequency signals.

Examples:

- Wi-Fi
    
- Bluetooth
    
- cellular networks
    

---

## Layer 1 Devices

Common examples:

- cables
    
- repeaters
    
- hubs
    
- antennas
    
- transceivers
    
- connectors
    

A traditional **hub** operates primarily at Layer 1.

It receives a signal and repeats it to other ports.

---

## Layer 1 Problems

Typical problems:

```text
Cable disconnected
Damaged cable
Bad connector
No signal
Weak wireless signal
Interference
Wrong transceiver
Faulty network interface
```

---

## Cybersecurity Relevance

Physical attacks can include:

- cable tapping
    
- unauthorized physical access
    
- network device theft
    
- wireless signal interception
    
- hardware tampering
    

For example, an attacker with physical access to networking infrastructure may be able to connect an unauthorized device.

---

# 4. Layer 2 — Data Link Layer

The Data Link layer handles communication between devices on the **same local network/link**.

Important concepts include:

- MAC addresses
    
- Ethernet frames
    
- switching
    
- VLANs
    
- ARP-related local-network behavior
    

Layer 2 is commonly divided conceptually into:

```text
LLC
Logical Link Control

MAC
Media Access Control
```

---

# MAC Address

A MAC address identifies a network interface at Layer 2.

Example:

```text
00:1A:2B:3C:4D:5E
```

Modern MAC addresses are generally 48 bits.

Example:

```text
00:1A:2B:3C:4D:5E
│
└── Hardware/interface identifier
```

MAC addresses are used for local Ethernet/Wi-Fi communication.

---

# Ethernet Frames

At Layer 2, data is encapsulated into a:

> **Frame**

Conceptually:

```text
+----------------+
| Destination MAC|
+----------------+
| Source MAC     |
+----------------+
| Type/Length    |
+----------------+
| Payload        |
+----------------+
| FCS            |
+----------------+
```

The exact Ethernet frame structure contains additional details, but these are the major fields you should understand initially.

---

# Switches

A traditional Ethernet switch primarily operates at Layer 2.

It maintains a:

> **MAC address table**

Example:

```text
MAC Address           Port
--------------------------------
AA:AA:AA:AA:AA:AA     1
BB:BB:BB:BB:BB:BB     2
CC:CC:CC:CC:CC:CC     4
```

If the switch knows where a destination MAC address exists, it can forward the frame to the appropriate port.

---

# VLANs

A **VLAN (Virtual LAN)** logically separates Layer-2 networks.

Example:

```text
VLAN 10 → Employees
VLAN 20 → Servers
VLAN 30 → Guest
```

Even if the machines are connected to the same physical switch infrastructure, VLANs can isolate their Layer-2 broadcast domains.

---

# Layer 2 Attacks

Important cybersecurity topics:

### MAC spoofing

An attacker changes the MAC address associated with their network interface.

### ARP spoofing

An attacker sends fraudulent ARP information.

Example:

```text
Victim
   ↓
Attacker
   ↓
Router
```

This can potentially enable:

- Man-in-the-Middle attacks
    
- traffic interception
    
- traffic manipulation
    

### VLAN attacks

Misconfiguration can potentially lead to VLAN-related attacks, such as VLAN hopping.

---

# 5. Layer 3 — Network Layer

Layer 3 is responsible primarily for:

- logical addressing
    
- routing
    
- packet forwarding
    

The most important protocol here is:

> **IP**

---

# IP Address

Example:

```text
192.168.1.10
```

IPv4 addresses are 32 bits.

Conceptually:

```text
192.168.1.10
│
├── Network portion
└── Host portion
```

The exact division depends on the subnet mask/prefix.

Example:

```text
192.168.1.10/24
```

means:

```text
Network: 192.168.1.0
Host:    .10
```

---

# Routers

Routers operate primarily at Layer 3.

They forward packets between different networks.

Example:

```text
192.168.1.0/24
       |
       | Router
       |
10.10.10.0/24
```

A router examines the destination IP address and determines where the packet should go.

---

# Routing

Suppose:

```text
Host A
192.168.1.10
```

wants to communicate with:

```text
Server
10.10.10.20
```

The destination is outside the local subnet.

Host A generally sends the packet to its:

> **Default gateway**

Example:

```text
Host
192.168.1.10
      |
      ↓
Gateway
192.168.1.1
      |
      ↓
Router
      |
      ↓
10.10.10.20
```

---

# Important Layer 3 Protocols

### IPv4

Internet Protocol version 4.

### IPv6

Internet Protocol version 6.

### ICMP

Used for network control and diagnostic messaging.

For example:

```bash
ping 192.168.1.1
```

uses ICMP Echo Request/Reply in the typical case.

### IPsec

Provides security mechanisms at the IP layer.

---

# Layer 3 Attacks

Examples include:

- IP spoofing
    
- ICMP abuse
    
- routing attacks
    
- route manipulation
    
- packet fragmentation abuse
    
- certain denial-of-service techniques
    

---

# 6. Layer 4 — Transport Layer

Layer 4 provides **end-to-end transport** between applications/processes.

The two major transport protocols are:

```text
TCP
UDP
```

---

# TCP

TCP is:

> Connection-oriented and reliable.

It provides mechanisms for:

- sequencing
    
- acknowledgments
    
- retransmission
    
- flow control
    
- congestion control
    

---

# TCP Three-Way Handshake

Before normal TCP data transmission, a connection is established.

```text
Client                  Server
  |                       |
  | ---- SYN -----------> |
  |                       |
  | <--- SYN/ACK -------- |
  |                       |
  | ---- ACK -----------> |
  |                       |
```

This is:

```text
SYN
SYN-ACK
ACK
```

---

# TCP Ports

Ports identify services/process endpoints.

Examples:

```text
22   SSH
25   SMTP
53   DNS
80   HTTP
443  HTTPS
```

A connection can be represented as:

```text
192.168.1.10:49152
        ↓
93.184.216.34:443
```

Here:

```text
Source IP:      192.168.1.10
Source port:    49152
Destination IP: 93.184.216.34
Destination port:443
```

---

# UDP

UDP is:

> Connectionless and lightweight.

It doesn't provide TCP-style:

- connection establishment
    
- acknowledgments
    
- retransmission
    
- ordered delivery
    

UDP is commonly used where low overhead or application-controlled reliability is useful.

Examples include:

- DNS
    
- DHCP
    
- streaming
    
- VoIP
    
- gaming
    
- QUIC
    

---

# TCP vs UDP

|Feature|TCP|UDP|
|---|---|---|
|Connection|Yes|No|
|Reliability|Yes|No built-in reliability|
|Ordering|Yes|No|
|Retransmission|Yes|No|
|Overhead|Higher|Lower|
|Typical use|HTTP/HTTPS, SSH|DNS, DHCP, VoIP|

---

# Layer 4 Security

Important topics:

- port scanning
    
- SYN scanning
    
- TCP reset attacks
    
- SYN floods
    
- UDP floods
    
- firewall filtering
    
- service enumeration
    

For penetration testing, Layer 4 is particularly important because services are exposed through **ports**.

Example:

```bash
nmap -sT 192.168.1.10
```

You are essentially investigating transport-layer services exposed by the target.

---

# 7. Layer 5 — Session Layer

The Session layer manages communication sessions between applications.

Responsibilities can include:

- session establishment
    
- session management
    
- session termination
    
- synchronization
    
- session recovery
    

Conceptually:

```text
Client
  |
  | Establish session
  ↓
Server
  |
  | Communication
  |
  | Synchronization
  |
  | Terminate session
```

---

## Important Note

In modern practical networking, Layers 5, 6, and 7 are often implemented together by application protocols and libraries rather than as completely separate layers.

That's why you won't always find a protocol that cleanly belongs only to Layer 5.

---

# Session Layer Security

Session-related security issues can include:

- session hijacking
    
- session fixation
    
- session token theft
    
- session management weaknesses
    
- improper session termination
    

For web security, session management is extremely important.

Example:

```text
Victim
   |
   | Login
   ↓
Server
   |
   | Session ID
   ↓
Browser
```

If an attacker obtains the session identifier, they may potentially impersonate the user.

---

# 8. Layer 6 — Presentation Layer

The Presentation layer deals with the **representation of data**.

It can handle:

- encoding
    
- serialization
    
- encryption
    
- decryption
    
- compression
    
- decompression
    
- data formatting
    

The purpose is to ensure that data is represented in a form that the receiving application can understand.

---

# Encoding

Example:

```text
Hello
```

could be represented using UTF-8 bytes.

Encoding is **not encryption**.

---

# Encryption

Encryption transforms plaintext into ciphertext.

Example:

```text
Plaintext
    ↓
Encryption
    ↓
Ciphertext
```

Only someone with the appropriate key should be able to recover the plaintext.

---

# Compression

Compression reduces data size.

Example:

```text
Large data
   ↓
Compression
   ↓
Smaller data
```

---

# Data Formats

Common representations include:

```text
JSON
XML
UTF-8
ASCII
JPEG
PNG
MPEG
```

Not all of these are strictly OSI Layer 6 protocols, but they illustrate the kinds of data representation issues associated conceptually with the Presentation layer.

---

# TLS

TLS is often discussed around the Presentation layer because it provides encryption for application communication.

For example:

```text
HTTP
  ↓
TLS
  ↓
TCP
  ↓
IP
  ↓
Ethernet
```

However, in real-world protocol stacks, assigning TLS to exactly one OSI layer is an oversimplification.

---

# 9. Layer 7 — Application Layer

The Application layer provides network functionality directly used by applications.

Examples:

```text
HTTP
HTTPS
DNS
SMTP
IMAP
POP3
FTP
SSH
DHCP
SNMP
```

---

# HTTP

When you visit:

```text
https://example.com
```

the browser communicates using HTTP semantics, usually protected by TLS.

Example request:

```http
GET / HTTP/1.1
Host: example.com
```

---

# DNS

DNS converts names into network information.

Example:

```text
example.com
     ↓
DNS
     ↓
93.184.216.34
```

DNS is extremely important during reconnaissance.

---

# SMTP

SMTP is primarily used for sending email.

Typical port:

```text
25
```

Other commonly encountered submission configurations include:

```text
587
465
```

---

# SSH

SSH provides secure remote access.

Default port:

```text
22
```

Example:

```bash
ssh user@192.168.1.10
```

---

# Layer 7 Security

Common application-layer vulnerabilities include:

- SQL injection
    
- XSS
    
- command injection
    
- path traversal
    
- SSRF
    
- authentication flaws
    
- authorization flaws
    
- insecure deserialization
    
- API vulnerabilities
    
- file upload vulnerabilities
    

This is particularly important for your **VAPT/web penetration-testing** work.

# 10. Encapsulation

Encapsulation occurs when data moves **down the protocol stack** on the sender.

Suppose you send:

```text
GET /login HTTP/1.1
```

Conceptually:

```text
Application
    ↓
Data

Transport
    ↓
TCP Segment

Network
    ↓
IP Packet

Data Link
    ↓
Ethernet Frame

Physical
    ↓
Bits
```

Each layer adds information required by that layer.

---

# Encapsulation Example

Imagine:

```text
Application Data
```

Layer 4 adds a TCP header:

```text
TCP Header
+
Application Data
```

Layer 3 adds an IP header:

```text
IP Header
+
TCP Header
+
Application Data
```

Layer 2 adds an Ethernet header/trailer:

```text
Ethernet Header
+
IP Header
+
TCP Header
+
Application Data
+
Ethernet Trailer
```

Then the physical layer transmits the resulting frame as bits/signals.

---

# 11. Decapsulation

The receiver performs the reverse operation.

Incoming:

```text
Bits
 ↓
Frame
 ↓
Packet
 ↓
Segment
 ↓
Data
```

Each layer examines and removes/processes its relevant header.

Conceptually:

```text
Physical
   ↓
Data Link
   ↓
Network
   ↓
Transport
   ↓
Session
   ↓
Presentation
   ↓
Application
```

Eventually the application receives the original data.

---

|Layer 6|Data|
|Layer 5|Data|

|Layer 2|Frame|
|Layer 1|Bits|

---

# Bits

Layer 1:

```text
101101001010
```

Physical signals represent these bits.

---

# Frame

Layer 2:

```text
Ethernet Frame
```

Contains things such as:

```text
Source MAC
Destination MAC
Payload
FCS
```

---

# Packet

Layer 3:

```text
IP Packet
```

Contains:

```text
Source IP
Destination IP
Payload
```

---

# Segment

```text
TCP Segment
```

```text

Acknowledgment Number

```

> **Datagram**

# Data

Layers 5–7 commonly use the generic term:

```text

```

# 13. Layer-to-Layer Communication

There are two concepts you should distinguish.

## Vertical communication

Inside a computer:

```text
Application
    ↕
Transport
    ↕
Network
    ↕
Data Link
    ↕
Physical
```

Each layer provides services to the layer above it and uses services from the layer below.

---

## Logical Peer-to-Peer Communication

Conceptually, the same layer on two different computers communicates with its peer.

Example:

```text
Computer A                    Computer B

Transport  <-------------->  Transport
Network    <-------------->  Network
Data Link  <-------------->  Data Link
Physical   <-------------->  Physical
```

But physically, the data travels down the sender's stack, across the network, and up the receiver's stack.

# 15. OSI Troubleshooting Methodology

The OSI model is extremely useful for troubleshooting because it allows you to isolate the problem layer by layer.

A practical approach is:

```text
Physical
   ↓
Data Link
   ↓
Network
   ↓
Transport
   ↓
Application
```

---

# Layer 1 Troubleshooting

Check:

```text
Is the cable connected?
Is the NIC enabled?
Are link LEDs active?
Is the Wi-Fi signal available?
Is the interface physically damaged?
```

Linux:

```bash
ip link
```

You can inspect interfaces and link state.

---

# Layer 2 Troubleshooting

Check:

```text
MAC address
ARP
VLAN
switch port
Wi-Fi association
```

Linux:

```bash
ip link
ip neigh
```

Example:

```bash
ip neigh
```

may show neighbor/ARP information.

---

# Layer 3 Troubleshooting

Check:

```text
IP address
subnet
default gateway
routing
ICMP connectivity
```

Commands:

```bash
ip addr
ip route
ping 192.168.1.1
```

---

# Layer 4 Troubleshooting

Suppose:

```text
ping 192.168.1.10
```

works, but:

```bash
ssh 192.168.1.10
```

doesn't.

The machine may be reachable at Layer 3 while the TCP service is unavailable.

Check:

```bash
nc -vz 192.168.1.10 22
```

or:

```bash
nmap -p 22 192.168.1.10
```

Potential causes:

- service isn't running
    
- firewall blocking port
    
- wrong port
    
- TCP filtering
    

---

# Layer 7 Troubleshooting

Suppose:

```text
TCP 443 → reachable
```

but the website isn't working correctly.

Now investigate:

```text
HTTP
TLS
DNS
application configuration
authentication
authorization
server errors
```

For example:

```bash
curl -v https://example.com
```

can provide useful application-layer information.

---

# Practical Troubleshooting Flow

A useful methodology:

```text
1. Physical
       ↓
2. Link
       ↓
3. IP
       ↓
4. Routing
       ↓
5. Port
       ↓
6. Protocol
       ↓
7. Application
```

Example:

```text
Can I see the network interface?
        ↓
Do I have link?
        ↓
Do I have an IP?
        ↓
Can I reach the gateway?
        ↓
Can I reach the destination?
        ↓
Is the port open?
        ↓
Is the service responding?
        ↓
Is the application functioning correctly?
```

This methodology is very useful during pentesting as well.

# 16. OSI vs TCP/IP Model

The TCP/IP model is the practical networking model associated with the Internet protocol suite.

A commonly taught mapping is:

| OSI            | TCP/IP                |
| -------------- | --------------------- |
| 7 Application  | Application           |
| 6 Presentation | Application           |
| 5 Session      | Application           |
| 4 Transport    | Transport             |
| 3 Network      | Internet              |
| 2 Data Link    | Link / Network Access |
| 1 Physical     | Link / Network Access |

Thus:

```text
OSI                         TCP/IP

Application ───────┐
Presentation ──────┤
Session ───────────┤
                   ↓
              Application

Transport ───────────→ Transport

Network ──────────────→ Internet

Data Link ────────┐
Physical ─────────┤
                  ↓
             Link / Network
                Access
```

---

# 17. OSI vs TCP/IP — Key Differences

|Feature|OSI|TCP/IP|
|---|---|---|
|Layers|7|Usually 4|
|Origin|ISO|DoD/DARPA Internet architecture|
|Purpose|Conceptual/reference model|Practical protocol suite/model|
|Session layer|Separate|Usually Application|
|Presentation layer|Separate|Usually Application|
|Physical layer|Separate|Usually combined with Link|
|Transport|Transport|Transport|
|Network|Network|Internet|
|Common use|Education, troubleshooting|Real-world Internet networking|

# 18. Important Cybersecurity Mapping

For VAPT, you should be able to connect attacks to layers.

|Layer|Security Topics|
|---|---|
|L1|Physical access, cable tapping, signal interception|
|L2|ARP spoofing, MAC spoofing, VLAN attacks|
|L3|IP spoofing, routing attacks, ICMP abuse|
|L4|Port scanning, SYN attacks, firewall filtering|
|L5|Session hijacking, session fixation|
|L6|TLS, encoding, encryption, serialization|
|L7|SQLi, XSS, SSRF, command injection, API attacks|

This isn't absolute—real attacks often cross multiple layers.

# 19. A Critical Concept: OSI Is a Model, Not a Perfect Description

Don't make the mistake of thinking:

> "Every real-world protocol belongs to exactly one OSI layer."

Real networking is messier.

For example:

### ARP

ARP is commonly associated with Layer 2/3 because it maps IP information to MAC information.

### TLS

TLS doesn't fit perfectly into one OSI layer.

### HTTP/3

HTTP/3 runs over QUIC, which runs over UDP.

Conceptually:

```text
HTTP/3
  ↓
QUIC
  ↓
UDP
  ↓
IP
  ↓
Ethernet/Wi-Fi
```

QUIC itself incorporates functionality that historically might have been associated with the transport layer and session/security mechanisms.

Therefore, use OSI primarily as a **conceptual and troubleshooting framework**, not as a rigid classification system.

# 20. OSI Model From a Pentester's Perspective

For penetration testing, think of the model like this:

```text
L7 ─── Application
       ↓
       Web/API/DNS/SMTP/SSH
       ↓
       Find vulnerabilities

L6 ─── Presentation
       ↓
       TLS/encoding/serialization
       ↓
       Inspect data protection

L5 ─── Session
       ↓
       Sessions/tokens
       ↓
       Test session security

L4 ─── Transport
       ↓
       TCP/UDP/ports
       ↓
       Enumerate services

L3 ─── Network
       ↓
       IP/routing/ICMP
       ↓
       Discover hosts/networks

L2 ─── Data Link
       ↓
       MAC/ARP/VLAN
       ↓
       Attack local network

L1 ─── Physical
       ↓
       cables/radio/hardware
       ↓
       Physical security
```

A practical reconnaissance chain might look like:

```text
Discover network
      ↓
Identify hosts
      ↓
Identify IP addresses
      ↓
Scan ports
      ↓
Identify services
      ↓
Enumerate protocols
      ↓
Enumerate applications
      ↓
Find vulnerabilities
      ↓
Exploit
```

# 21. What You Should Memorize

For cybersecurity interviews and practical networking, know these relationships very well:

```text
Layer 1 → Bits → Physical
Layer 2 → Frames → MAC → Switch
Layer 3 → Packets → IP → Router
Layer 4 → Segments/Datagrams → Ports → TCP/UDP
Layer 5 → Sessions
Layer 6 → Encoding/Encryption/Compression
Layer 7 → Data → Applications/Protocols
```

And the complete flow:

```text
Application Data
       ↓
   TCP Segment
       ↓
    IP Packet
       ↓
 Ethernet Frame
       ↓
      Bits
```

At the destination:

```text
      Bits
       ↓
 Ethernet Frame
       ↓
    IP Packet
       ↓
   TCP Segment
       ↓
Application Data
```

### The most important distinction for VAPT

Remember:

**MAC → Layer 2**

**IP → Layer 3**

**Port → Layer 4**

**Application/service → Layer 7**

So if you see:

```text
192.168.1.50:443
```

you should immediately understand:

```text
192.168.1.50 → Layer 3 (IP)
443           → Layer 4 (TCP/UDP port)
HTTPS         → Layer 7 application protocol
Ethernet/Wi-Fi → Layer 2
Physical signal → Layer 1
```

That mental mapping is much more useful in real pentesting than simply memorizing the seven layer names.
