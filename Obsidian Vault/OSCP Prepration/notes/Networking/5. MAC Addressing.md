# 5. MAC Addressing — Detailed & In-Depth

MAC addressing is one of the most important concepts in **Layer 2 networking**. If you understand MAC addresses properly, Ethernet switching, ARP, VLANs, Wi-Fi networking, packet analysis with Wireshark, and many network-security attacks become much easier to understand.

---

# 1. What Is a MAC Address?

**MAC** stands for **Media Access Control**.

A MAC address is a Layer 2 address associated with a network interface. Ethernet uses MAC addresses to identify the **source and destination interfaces on a local Layer 2 network**.

For example:

```text
PC A
IP: 192.168.1.10
MAC: 00:1A:2B:3C:4D:5E
```

Another machine:

```text
PC B
IP: 192.168.1.20
MAC: 08:00:27:AA:BB:CC
```

When PC A sends an Ethernet frame directly to PC B:

```text
Source MAC      Destination MAC
00:1A:2B:3C:4D:5E → 08:00:27:AA:BB:CC
```

The switch primarily uses these MAC addresses to decide where to forward the Ethernet frame.

### MAC vs IP

A very important distinction:

|Address|Layer|Purpose|
|---|--:|---|
|MAC|Layer 2|Local network/interface identification|
|IP|Layer 3|Logical addressing/routing between networks|
|Port|Layer 4|Identifies application/service|

Example:

```text
MAC:  00:1A:2B:3C:4D:5E
IP:   192.168.1.10
Port: 443
```

Think of it approximately as:

```text
MAC → Which interface on this local network?
IP  → Which host/network should packets reach?
Port → Which application/service?
```

This isn't a perfect analogy because MAC addresses aren't globally equivalent to physical locations, but it's useful for understanding the roles.

---

# 2. MAC Address Structure

A traditional Ethernet MAC address is **48 bits** long.

That means:

```text
48 bits = 6 bytes = 6 octets
```

It's commonly written in hexadecimal.

Example:

```text
00:1A:2B:3C:4D:5E
```

Each hexadecimal digit represents 4 bits.

Therefore:

```text
00:1A:2B:3C:4D:5E
 ↓  ↓  ↓  ↓  ↓  ↓
8   8   8   8   8   8 bits
```

Total:

```text
8 × 6 = 48 bits
```

---

## 2.1 Hexadecimal Representation

One hexadecimal digit represents:

```text
0–9
A–F
```

Examples:

```text
0 = 0000
1 = 0001
A = 1010
F = 1111
```

So:

```text
00:1A:2B:3C:4D:5E
```

is just a human-readable representation of a 48-bit value.

Other notation styles include:

```text
00:1A:2B:3C:4D:5E
00-1A-2B-3C-4D-5E
001A.2B3C.4D5E
001A2B3C4D5E
```

The exact notation depends on the operating system or networking equipment.

---

# 3. The 48-Bit MAC Address Structure

A traditional MAC address can conceptually be divided into:

```text
|-------- 24 bits --------|-------- 24 bits --------|
|       OUI / prefix      |      device portion    |
```

Historically, the first 24 bits identify the organization associated with the address block.

Example:

```text
00:1A:2B:3C:4D:5E
```

Conceptually:

```text
00:1A:2B    3C:4D:5E
   │             │
   │             └── Interface/device identifier
   └──────────────── OUI/prefix
```

However, **do not assume every MAC address literally follows a manufacturer-prefix/device-ID model**. Modern MAC allocation includes different address types, including locally administered and randomized addresses.

---

# 4. Important Bits in a MAC Address

The first octet contains two particularly important bits.

Consider:

```text
First octet
     ↓
    00
```

Binary:

```text
00000000
│      │
│      └── I/G bit
└───────── U/L bit
```

More precisely:

```text
Bit 0 → I/G (Individual/Group)
Bit 1 → U/L (Universal/Local)
```

These two bits determine important properties of the address.

---

# 5. I/G Bit — Unicast vs Multicast

The **Individual/Group bit** determines whether the MAC address represents an individual destination or a group.

### I/G = 0

The address is an **individual/unicast address**.

### I/G = 1

The address is a **group address**, such as multicast.

Example:

```text
00:11:22:33:44:55
```

First octet:

```text
00 = 00000000
          ↑
        I/G = 0
```

Therefore it is a unicast MAC address.

Example:

```text
01:00:5E:xx:xx:xx
```

First octet:

```text
01 = 00000001
          ↑
        I/G = 1
```

Therefore it is a group/multicast MAC address.

---

# 6. U/L Bit — Universal vs Local

The second important bit is the **U/L (Universal/Local) bit**.

### U/L = 0

Universally administered address.

### U/L = 1

Locally administered address.

For example:

```text
00:11:22:33:44:55
```

First octet:

```text
00 = 00000000
      ↑
     U/L = 0
```

This indicates a universally administered address.

Example:

```text
02:11:22:33:44:55
```

First octet:

```text
02 = 00000010
      ↑
     U/L = 1
```

This indicates a locally administered address.

---

# 7. Unicast MAC Address

A **unicast MAC address** identifies a specific interface as the destination.

Example:

```text
00:11:22:33:44:55
```

Suppose:

```text
PC A
MAC = 00:11:22:33:44:55
```

PC B wants to send a frame specifically to PC A:

```text
Destination MAC:
00:11:22:33:44:55
```

The Ethernet frame looks conceptually like:

```text
+-------------------------+
| Destination MAC         |
| 00:11:22:33:44:55       |
+-------------------------+
| Source MAC              |
| 08:00:27:AA:BB:CC       |
+-------------------------+
| EtherType               |
+-------------------------+
| Payload                 |
+-------------------------+
| FCS                     |
+-------------------------+
```

A switch examines the destination MAC and forwards the frame toward the corresponding switch port.

---

# 8. Multicast MAC Address

Multicast means:

> **One sender → multiple interested receivers**

A multicast MAC address represents a group rather than a single interface.

Example IPv4 multicast MAC addresses commonly begin with:

```text
01:00:5E
```

For example:

```text
01:00:5E:00:00:01
```

The idea is:

```text
             ┌── Host A
             │
Sender ──────┼── Host B
             │
             └── Host C
```

Instead of creating separate unicast traffic for every receiver, multicast allows traffic to be associated with a group.

---

# 9. IPv4 Multicast and MAC Addresses

IPv4 multicast addresses range from:

```text
224.0.0.0
to
239.255.255.255
```

Ethernet maps IPv4 multicast addresses to multicast MAC addresses beginning with:

```text
01:00:5E
```

For example:

```text
IPv4 multicast:
224.0.0.1
```

maps to:

```text
01:00:5E:00:00:01
```

There is an important limitation here:

**IPv4 multicast-to-MAC mapping is not one-to-one.**

Multiple IPv4 multicast addresses can map to the same Ethernet MAC address because only part of the IPv4 multicast address is represented in the MAC mapping.

This is an important networking detail when analyzing multicast traffic.

---

# 10. Broadcast MAC Address

Broadcast means:

> **One sender → everyone on the local Layer 2 broadcast domain**

The Ethernet broadcast MAC address is:

```text
FF:FF:FF:FF:FF:FF
```

In binary:

```text
11111111:11111111:11111111:
11111111:11111111:11111111
```

All 48 bits are `1`.

---

## Example

Suppose:

```text
PC A
MAC: 00:11:22:33:44:55
```

PC A sends:

```text
Destination:
FF:FF:FF:FF:FF:FF
```

Every device in the relevant Layer 2 broadcast domain receives the Ethernet frame.

Conceptually:

```text
                  ┌── PC B
                  │
PC A ── Switch ───┼── PC C
                  │
                  ├── PC D
                  │
                  └── PC E
```

This is why broadcast traffic can affect every device in a broadcast domain.

---

# 11. Unicast vs Multicast vs Broadcast

|Type|Destination|Example|
|---|---|---|
|Unicast|One interface|`00:11:22:33:44:55`|
|Multicast|Group|`01:00:5E:...`|
|Broadcast|Everyone in L2 broadcast domain|`FF:FF:FF:FF:FF:FF`|

Conceptually:

```text
Unicast:

A ─────────→ B


Multicast:

       ┌── B
A ─────┼── C
       └── D


Broadcast:

       ┌── B
       ├── C
A ─────┼── D
       └── E
```

---

# 12. OUI — Organizationally Unique Identifier

**OUI** stands for:

> Organizationally Unique Identifier

The OUI is traditionally the first **24 bits** of a MAC address.

Example:

```text
00:1A:2B:3C:4D:5E
└───────┘
  24 bits
```

The OUI identifies an organization associated with a MAC address allocation.

Historically, vendors received address blocks from the IEEE.

For example, a vendor could receive a prefix and assign addresses from its allocated space.

---

# 13. Why OUI Is Useful

When doing network reconnaissance or packet analysis, MAC addresses can sometimes provide useful information about the manufacturer or organization associated with the address.

For example:

```text
MAC:
3C:52:82:AA:BB:CC
```

You could perform an OUI lookup to determine the registered organization associated with the prefix.

This can help during:

- Network inventory
    
- Incident response
    
- Wi-Fi analysis
    
- Packet analysis
    
- Device identification
    
- Network troubleshooting
    

But remember:

**OUI does not reliably tell you the current physical device owner.**

MAC addresses can be changed, randomized, virtualized, or locally administered.

---

# 14. Locally Administered MAC Addresses

A **locally administered address (LAA)** is an address where the U/L bit is set to `1`.

Example:

```text
02:AA:BB:CC:DD:EE
```

First octet:

```text
02
```

Binary:

```text
00000010
      ↑
     U/L = 1
```

Therefore:

```text
Locally administered = YES
```

---

# 15. Why Are Locally Administered Addresses Used?

They are useful when the MAC address needs to be assigned locally rather than using a universally assigned vendor address.

Common situations include:

- Virtual machines
    
- Containers
    
- Hypervisors
    
- Network testing
    
- Software-defined networking
    
- MAC randomization
    
- Certain operating-system networking features
    
- Network interface configuration
    

For example, a virtual machine may have:

```text
02:00:00:12:34:56
```

instead of a vendor-assigned physical NIC MAC.

---

# 16. MAC Randomization

Modern devices, particularly Wi-Fi clients, may use MAC randomization.

Instead of always exposing the same hardware-associated MAC:

```text
AA:BB:CC:11:22:33
```

the device may use another locally administered MAC:

```text
A2:14:7C:91:33:20
```

This can make passive tracking more difficult.

This is particularly relevant to:

- Wi-Fi networks
    
- Public hotspots
    
- Privacy
    
- Device tracking
    
- Wireless reconnaissance
    

Therefore, seeing a MAC address does **not necessarily mean** you can permanently identify a physical device.

---

# 17. MAC Address Tables

Now we reach one of the most important concepts for understanding Ethernet switches.

A switch maintains a **MAC address table**, sometimes called:

- CAM table
    
- Forwarding database
    
- FDB
    
- MAC table
    

The table associates:

```text
MAC address → Switch port
```

For example:

```text
MAC Address          Port
--------------------------------
00:11:22:33:44:55    Gi0/1
00:AA:BB:CC:DD:EE    Gi0/2
08:00:27:12:34:56    Gi0/3
```

The switch uses this information to forward Ethernet frames efficiently.

---

# 18. How a Switch Learns MAC Addresses

Suppose PC A is connected to port 1.

```text
PC A
MAC = AA:AA:AA:AA:AA:AA

       │
       │
     Port 1
       │
   ┌───┴───┐
   │ Switch│
   └───────┘
```

PC A sends a frame.

The switch examines the:

```text
Source MAC
```

It learns:

```text
AA:AA:AA:AA:AA:AA → Port 1
```

This is called **source MAC learning**.

---

# 19. Example of MAC Learning

Imagine:

```text
PC A → Port 1
PC B → Port 2
PC C → Port 3
```

Initially:

```text
MAC Table

Empty
```

PC A sends a frame:

```text
Source:
AA:AA:AA:AA:AA:AA
```

Switch learns:

```text
AA:AA:AA:AA:AA:AA → Port 1
```

Then PC B sends:

```text
BB:BB:BB:BB:BB:BB
```

Switch learns:

```text
AA:AA:AA:AA:AA:AA → Port 1
BB:BB:BB:BB:BB:BB → Port 2
```

Eventually:

```text
MAC Table

AA:AA:AA:AA:AA:AA → Port 1
BB:BB:BB:BB:BB:BB → Port 2
CC:CC:CC:CC:CC:CC → Port 3
```

---

# 20. How a Switch Forwards a Known Unicast

Suppose:

```text
PC A → PC B
```

The switch has:

```text
AA:AA:AA:AA:AA:AA → Port 1
BB:BB:BB:BB:BB:BB → Port 2
```

PC A sends:

```text
Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
BB:BB:BB:BB:BB:BB
```

The switch searches its MAC table:

```text
BB:BB:BB:BB:BB:BB → Port 2
```

It sends the frame only through Port 2.

```text
Port 1 ── PC A
          │
       Switch
          │
Port 2 ── PC B
```

This is why switches are much more efficient than simply flooding every frame everywhere.

---

# 21. Unknown Unicast

What happens if the switch doesn't know the destination MAC?

Suppose:

```text
Destination:
DD:DD:DD:DD:DD:DD
```

but the MAC table doesn't contain it.

The switch treats it as an **unknown unicast** and generally floods the frame within the relevant VLAN/broadcast domain, except back out the ingress port.

Conceptually:

```text
             ┌── PC B
             │
PC A ─ Switch├── PC C
             │
             └── PC D
```

The switch sends the frame toward the other relevant ports because it doesn't know where the destination is.

When the destination responds, the switch can learn its source MAC.

---

# 22. Broadcast Forwarding

If the destination is:

```text
FF:FF:FF:FF:FF:FF
```

the frame is broadcast.

The switch forwards it throughout the relevant Layer 2 broadcast domain/VLAN, subject to switch configuration and features such as VLAN boundaries or storm-control mechanisms.

---

# 23. MAC Table Aging

MAC table entries aren't necessarily permanent.

Switches typically use an **aging timer**.

For example:

```text
MAC:
AA:AA:AA:AA:AA:AA

Port:
Gi0/1

Age:
recent
```

If the switch doesn't see traffic from that MAC for some time, the entry can expire.

This prevents stale information from remaining indefinitely.

---

# 24. MAC Address Table Example

Suppose a switch has:

```text
             Switch
          ┌───────────┐
          │           │
       Gi0/1        Gi0/2
          │           │
        PC A         PC B
```

PC A:

```text
MAC = 00:11:22:33:44:55
```

PC B:

```text
MAC = 66:77:88:99:AA:BB
```

The switch may have:

```text
VLAN    MAC                  Port
--------------------------------------
10      00:11:22:33:44:55   Gi0/1
10      66:77:88:99:AA:BB   Gi0/2
```

Notice that MAC tables are often **VLAN-aware**.

The same MAC value can potentially appear in different VLAN contexts.

---

# 25. MAC Address Spoofing

**MAC spoofing** means changing the MAC address presented by a network interface.

Normally:

```text
Hardware/interface MAC
        ↓
00:11:22:33:44:55
```

After configuration:

```text
Reported MAC
        ↓
02:AA:BB:CC:DD:EE
```

The operating system or network stack can present the new address to the network.

---

# 26. Why Is MAC Spoofing Possible?

A MAC address is not normally cryptographically authenticated by Ethernet itself.

The frame contains:

```text
Source MAC
Destination MAC
```

The network generally cannot assume that the source MAC value is trustworthy merely because it appears in the Ethernet header.

Therefore:

```text
"I am AA:BB:CC:DD:EE:FF"
```

is not inherently proof that the sender owns that address.

This is an important security property.

---

# 27. Legitimate Uses of MAC Spoofing

MAC changes aren't inherently malicious.

They can be useful for:

### Testing

Testing network access-control policies.

### Troubleshooting

Testing whether network behavior depends on a particular MAC.

### Privacy

Using randomized addresses on Wi-Fi.

### Virtualization

Generating MAC addresses for virtual interfaces.

### Network migration

Replacing hardware while maintaining a MAC-dependent configuration in controlled environments.

---

# 28. Security Uses of MAC Spoofing

Attackers may attempt MAC spoofing to bypass weak network controls.

For example, suppose an organization incorrectly relies only on:

```text
Allowed MAC:
AA:BB:CC:DD:EE:FF
```

An attacker who discovers that MAC may attempt to configure their interface to use the same address.

This demonstrates an important principle:

> **MAC addresses are identifiers, not strong authentication credentials.**

---

# 29. MAC Address Filtering

MAC filtering means allowing or denying devices based on their MAC addresses.

Example:

```text
Allowed:

00:11:22:33:44:55
00:AA:BB:CC:DD:EE
08:00:27:12:34:56
```

A network device may permit only these addresses.

This can exist in:

- Wi-Fi access points
    
- Switches
    
- Network access-control systems
    
- Enterprise networks
    

---

# 30. Why MAC Filtering Is Not Strong Authentication

Suppose:

```text
Allowed MAC:
AA:BB:CC:DD:EE:FF
```

An attacker discovers that MAC.

If the network's security model relies only on MAC filtering, the attacker may attempt to use:

```text
AA:BB:CC:DD:EE:FF
```

on another interface.

Therefore:

```text
MAC filtering ≠ cryptographic authentication
```

Strong enterprise networks generally use additional controls such as:

- 802.1X
    
- EAP authentication
    
- WPA2/WPA3 Enterprise
    
- NAC
    
- Certificates
    
- Identity-based policies
    

MAC filtering can still be useful as an administrative control, but it should not be treated as a strong standalone authentication mechanism.

---

# 31. MAC Address Filtering vs Port Security

These concepts are related but different.

### MAC filtering

Often means:

> Permit or deny particular MAC addresses.

### Switch port security

Can enforce policies such as:

```text
Port Gi0/1:
Maximum MAC addresses = 1
Allowed/sticky MAC = AA:AA:AA:AA:AA:AA
```

If another MAC appears:

```text
Violation
```

The switch can be configured to:

- Drop frames
    
- Generate alerts
    
- Restrict the port
    
- Shut down the port
    

Exact behavior depends on the switch configuration/vendor.

---

# 32. MAC Spoofing vs MAC Filtering

Consider:

```text
Network policy:

MAC AA:AA:AA:AA:AA:AA → Allowed
```

Attacker:

```text
Real MAC:
BB:BB:BB:BB:BB:BB
```

They change their interface identity:

```text
Spoofed MAC:
AA:AA:AA:AA:AA:AA
```

If the network uses only weak MAC filtering, the attacker might appear to satisfy the MAC-based rule.

This is one reason network security should use **multiple layers of controls**.

---

# 33. ARP — Address Resolution Protocol

Now we connect MAC addresses with IP addresses.

ARP is used in **IPv4 Ethernet networks** to determine:

> Which MAC address corresponds to this IPv4 address on the local network?

Suppose:

```text
PC A

IP:
192.168.1.10

MAC:
AA:AA:AA:AA:AA:AA
```

PC A wants to communicate with:

```text
192.168.1.20
```

But it needs the destination MAC address to construct the Ethernet frame.

So it uses ARP.

---

# 34. Why Do We Need ARP?

IP operates at Layer 3.

Ethernet operates at Layer 2.

Suppose:

```text
IP destination:
192.168.1.20
```

The Ethernet frame still requires:

```text
Destination MAC:
??
```

Therefore the host needs to resolve:

```text
IPv4 address
     ↓
MAC address
```

ARP performs this mapping.

---

# 35. ARP Request

Suppose:

```text
PC A
IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA
```

PC A wants:

```text
192.168.1.20
```

It doesn't know the MAC.

It sends an ARP request approximately meaning:

> "Who has 192.168.1.20? Tell 192.168.1.10."

The Ethernet destination is:

```text
FF:FF:FF:FF:FF:FF
```

Therefore the ARP request is broadcast at Layer 2.

---

# 36. ARP Request Example

```text
PC A
192.168.1.10
AA:AA:AA:AA:AA:AA
       │
       │ ARP Request
       │
       ▼
   Broadcast
FF:FF:FF:FF:FF:FF
       │
 ┌─────┼─────┐
 ▼     ▼     ▼
PC B  PC C  PC D
```

All hosts in the local broadcast domain can receive the ARP request.

Only the host owning:

```text
192.168.1.20
```

should normally respond.

---

# 37. ARP Reply

Suppose PC B owns:

```text
IP:
192.168.1.20

MAC:
BB:BB:BB:BB:BB:BB
```

PC B responds:

```text
192.168.1.20 is at
BB:BB:BB:BB:BB:BB
```

Now PC A knows:

```text
192.168.1.20
        ↓
BB:BB:BB:BB:BB:BB
```

PC A can construct the Ethernet frame:

```text
Destination MAC:
BB:BB:BB:BB:BB:BB

Source MAC:
AA:AA:AA:AA:AA:AA
```

---

# 38. ARP Cache

Hosts usually don't perform ARP for every single packet.

They maintain an **ARP cache/table**.

Example:

```text
IP Address       MAC Address
-----------------------------------
192.168.1.1      11:22:33:44:55:66
192.168.1.20     BB:BB:BB:BB:BB:BB
192.168.1.30     CC:CC:CC:CC:CC:CC
```

When PC A needs:

```text
192.168.1.20
```

it checks its ARP cache.

If the mapping exists and is usable:

```text
192.168.1.20 → BB:BB:BB:BB:BB:BB
```

it can immediately construct the Ethernet frame.

---

# 39. ARP Resolution Process

The complete process is:

```text
Application
     ↓
IPv4 destination
     ↓
Check routing decision
     ↓
Is destination on local network?
     ↓
Yes
     ↓
Check ARP cache
     ↓
MAC known?
   /     \
 Yes      No
  │        │
  │     ARP Request
  │        ↓
  │     ARP Reply
  │        ↓
  └────→ MAC obtained
             ↓
       Ethernet Frame
             ↓
          Switch
             ↓
       Destination
```

---

# 40. What If the Destination Is on Another Network?

This is extremely important.

Suppose:

```text
PC:
192.168.1.10

Destination:
8.8.8.8
```

The destination is not on the local subnet.

The PC does **not** ARP for:

```text
8.8.8.8
```

Instead, it ARPs for the **default gateway's local IP address**.

For example:

```text
Default gateway:
192.168.1.1
```

PC A resolves:

```text
192.168.1.1
        ↓
Gateway MAC
```

Then:

```text
Ethernet Destination MAC
        ↓
Router's MAC
```

while the IP destination remains:

```text
8.8.8.8
```

---

# 41. This Is a Critical Concept

Suppose:

```text
PC:
IP  = 192.168.1.10
MAC = AA:AA:AA:AA:AA:AA

Router:
IP  = 192.168.1.1
MAC = RR:RR:RR:RR:RR:RR

Internet server:
IP = 8.8.8.8
```

The PC sends:

```text
Ethernet:

Source MAC:
AA:AA:AA:AA:AA:AA

Destination MAC:
RR:RR:RR:RR:RR:RR
```

But inside the IP packet:

```text
Source IP:
192.168.1.10

Destination IP:
8.8.8.8
```

Therefore:

> **The Ethernet destination MAC is the next hop, not necessarily the final IP destination.**

This is one of the most important concepts in networking.

---

# 42. MAC Address Changes Across Routers

Suppose:

```text
PC → Router 1 → Router 2 → Server
```

The Layer 2 Ethernet frame is local to each link.

For example:

### First link

```text
Source MAC:
PC

Destination MAC:
Router 1
```

Router 1 receives the frame.

It removes the old Ethernet header and forwards the IP packet using a new Layer 2 frame on the next interface.

### Second link

```text
Source MAC:
Router 1/next-hop interface

Destination MAC:
Router 2
```

Therefore, MAC addresses generally change at every Layer 3 hop.

The IP packet, subject to normal routing/NAT/etc., continues toward the destination.

---

# 43. ARP Packet Structure

An ARP message contains information such as:

```text
Hardware type
Protocol type
Hardware address length
Protocol address length
Operation
Sender hardware address
Sender protocol address
Target hardware address
Target protocol address
```

For Ethernet + IPv4, commonly:

```text
Hardware type:
Ethernet

Protocol:
IPv4

Hardware address length:
6 bytes

Protocol address length:
4 bytes
```

---

# 44. ARP Request Example

Conceptually:

```text
Sender MAC:
AA:AA:AA:AA:AA:AA

Sender IP:
192.168.1.10

Target MAC:
00:00:00:00:00:00

Target IP:
192.168.1.20
```

The target MAC may be unknown/zeroed in the ARP request because that's exactly what the sender is trying to discover.

Ethernet destination:

```text
FF:FF:FF:FF:FF:FF
```

---

# 45. ARP Reply Example

The target host responds:

```text
Sender MAC:
BB:BB:BB:BB:BB:BB

Sender IP:
192.168.1.20

Target MAC:
AA:AA:AA:AA:AA:AA

Target IP:
192.168.1.10
```

Now PC A knows the mapping.

---

# 46. ARP Security Problem

ARP has a fundamental weakness:

**Traditional ARP does not provide cryptographic authentication of ARP messages.**

A host can receive an ARP message claiming:

```text
192.168.1.1 is at
AA:BB:CC:DD:EE:FF
```

Without additional security controls, hosts may accept incorrect information.

This enables attacks such as:

> **ARP spoofing / ARP poisoning**

---

# 47. ARP Spoofing Concept

Imagine:

```text
Victim
192.168.1.10

Gateway
192.168.1.1

Attacker
192.168.1.50
```

Normally:

```text
192.168.1.1
      ↓
Gateway MAC
```

An attacker may attempt to convince the victim:

```text
192.168.1.1
      ↓
Attacker MAC
```

Then the victim may send traffic intended for the gateway toward the attacker.

This is fundamentally different from merely changing one's own MAC address.

### MAC spoofing

Changes the identity presented by an interface.

### ARP spoofing

Manipulates **IP-to-MAC resolution information** used by hosts.

---

# 48. ARP Spoofing Can Enable MITM

If an attacker successfully poisons ARP mappings and forwards traffic appropriately, they can potentially position themselves between two hosts:

```text
Victim
   │
   ▼
Attacker
   │
   ▼
Gateway
```

Instead of:

```text
Victim ─────────→ Gateway
```

the logical path becomes:

```text
Victim → Attacker → Gateway
```

This is commonly called a:

> **Man-in-the-Middle (MITM)** position.

Modern encrypted protocols such as properly configured HTTPS significantly limit what an attacker can read or modify at the application layer, even if they can observe or forward the traffic.

---

# 49. ARP Spoofing vs MAC Spoofing

These are frequently confused.

|Feature|MAC Spoofing|ARP Spoofing|
|---|---|---|
|Changes interface MAC identity|Yes|Not necessarily|
|Manipulates ARP cache|Not necessarily|Yes|
|Targets IP → MAC mapping|No|Yes|
|Can facilitate MITM|Potentially|Yes|
|Layer|Layer 2 identity|Layer 2/IPv4 resolution mechanism|
|Primary mechanism|Interface configuration|Forged/manipulated ARP messages|

---

# 50. Security Controls Against ARP Attacks

Enterprise switches can use technologies such as:

### Dynamic ARP Inspection (DAI)

The switch validates ARP messages against trusted bindings.

Conceptually:

```text
ARP packet
    ↓
Switch inspection
    ↓
Valid binding?
   /     \
 Yes      No
 ↓        ↓
Forward   Drop
```

---

### DHCP Snooping

The switch builds trusted IP/MAC/interface bindings from DHCP activity.

For example:

```text
MAC:
AA:AA:AA:AA:AA:AA

IP:
192.168.1.10

Port:
Gi0/5
```

That information can then support other security mechanisms such as Dynamic ARP Inspection.

---

### Static ARP

Administrators can manually configure mappings for particularly important hosts, although this doesn't scale well for large networks.

---

### VLAN Segmentation

Separating devices into different VLANs reduces the size of Layer 2 broadcast domains and limits where ARP traffic can propagate.

---

# 51. MAC Address and VLANs

A MAC address operates within a Layer 2 domain.

Suppose:

```text
VLAN 10
    PC A
    PC B

VLAN 20
    PC C
    PC D
```

Broadcast traffic in VLAN 10 doesn't normally cross into VLAN 20 at Layer 2.

Therefore:

```text
VLAN 10 broadcast domain
        ≠
VLAN 20 broadcast domain
```

This is why VLANs are important for network segmentation.

---

# 52. MAC Address and Switch Port

A switch essentially creates a relationship:

```text
MAC → VLAN → Port
```

For example:

```text
MAC                  VLAN     Port
----------------------------------------
AA:AA:AA:AA:AA:AA    10       Gi0/1
BB:BB:BB:BB:BB:BB    10       Gi0/2
CC:CC:CC:CC:CC:CC    20       Gi0/3
```

This allows the switch to make forwarding decisions.

---

# 53. MAC Address in an Ethernet Frame

A basic Ethernet II frame contains:

```text
+-------------------------+
| Destination MAC  6 B    |
+-------------------------+
| Source MAC       6 B    |
+-------------------------+
| EtherType         2 B   |
+-------------------------+
| Payload                 |
+-------------------------+
| FCS               4 B   |
+-------------------------+
```

The MAC addresses are therefore directly inside the Ethernet frame.

Example:

```text
Destination:
08:00:27:AA:BB:CC

Source:
00:11:22:33:44:55
```

---

# 54. Source MAC vs Destination MAC

Consider:

```text
PC A → PC B
```

The frame contains:

```text
Source MAC:
PC A

Destination MAC:
PC B
```

At the next router hop:

```text
Source MAC:
Router interface

Destination MAC:
Next-hop device
```

The Layer 2 addresses describe the **current local Ethernet hop**.

---

# 55. MAC Addresses in Wireshark

When performing network analysis, you'll frequently see:

```text
Ethernet II
    Destination: xx:xx:xx:xx:xx:xx
    Source: xx:xx:xx:xx:xx:xx
    Type: IPv4
```

For example:

```text
Ethernet II
    Src: 00:11:22:33:44:55
    Dst: AA:BB:CC:DD:EE:FF
    Type: IPv4
```

Then underneath:

```text
Internet Protocol Version 4
    Src: 192.168.1.10
    Dst: 192.168.1.20
```

And possibly:

```text
Transmission Control Protocol
    Src Port: 51532
    Dst Port: 443
```

So you can see the encapsulation:

```text
Ethernet
   ↓
IPv4
   ↓
TCP
   ↓
TLS/HTTP/etc.
```

# 57. MAC Addresses and Virtual Machines

Virtualization makes MAC addressing particularly interesting.

A VM typically has a virtual network interface:

```text
VM
 │
 └── vNIC
       │
       └── MAC
```

For example:

```text
VM 1:
00:0C:29:AA:BB:CC

VM 2:
00:0C:29:DD:EE:FF
```

The hypervisor manages the relationship between:

```text
Virtual NIC
      ↓
Virtual MAC
      ↓
Virtual switch
      ↓
Physical NIC
      ↓
Physical network
```

This is important when building cybersecurity labs.

---

# 58. MAC Address vs NIC

These aren't exactly the same thing.

### NIC

Network Interface Controller/interface.

### MAC address

The Layer 2 address associated with an interface.

A machine can have multiple interfaces:

```text
Laptop

Ethernet NIC
MAC: AA:AA:AA:AA:AA:AA

Wi-Fi NIC
MAC: BB:BB:BB:BB:BB:BB

Virtual NIC
MAC: CC:CC:CC:CC:CC:CC
```

Therefore:

> One computer can have multiple MAC addresses.

---

# 59. Can a Device Have Multiple MAC Addresses?

Absolutely.

For example:

```text
Physical Ethernet interface
        ↓
MAC #1

Wi-Fi interface
        ↓
MAC #2

Bluetooth networking
        ↓
Different address mechanism

Docker bridge/interface
        ↓
MAC #3

VMware virtual interface
        ↓
MAC #4
```

So MAC addresses identify **network interfaces/Layer 2 endpoints**, not necessarily entire computers.

---

# 60. Important Cybersecurity Perspective

When doing network reconnaissance, don't automatically assume:

```text
1 MAC = 1 physical device
```

There may be:

- Virtual machines
    
- Containers
    
- Phones
    
- Access points
    
- Bridges
    
- Hypervisors
    
- MAC randomization
    
- Network namespaces
    
- Multiple interfaces
    
- Spoofed addresses
    

Therefore MAC-based identification must be interpreted in context.

# 61. Complete Example: PC A Communicating With PC B

Let's put everything together.

Suppose:

```text
PC A

IP:
192.168.1.10

MAC:
AA:AA:AA:AA:AA:AA
```

PC B:

```text
IP:
192.168.1.20

MAC:
BB:BB:BB:BB:BB:BB
```

PC A wants to send an HTTPS request to PC B.

---

### Step 1 — Application

```text
HTTPS request
```

---

### Step 2 — TCP

```text
Source port:
50000

Destination:
443
```

---

### Step 3 — IP

```text
Source IP:
192.168.1.10

Destination IP:
192.168.1.20
```

---

### Step 4 — ARP

PC A checks:

```text

```

If unknown:

```text

```


```text
        ↓

```

### Step 5 — Ethernet

PC A creates:

```text

BB:BB:BB:BB:BB:BB
```

```text

    ↓

    ↓

    ↓
```

If you're studying networking for cybersecurity, memorize these relationships:

```text
Layer 2 address
```

```text
One destination
```

```text
Group of destinations
```

```text

Traditional first 24 bits
```

```text
Allow/deny based on MAC
```

```text
MAC address ≠ strong authentication
```

# 63. One Complete Mental Model

Keep this diagram in your head:

```text
                         APPLICATION
                              │
                              ▼
                         TCP / UDP
                              │
                              ▼
                         IP ADDRESS
                       192.168.1.20
                              │
                    ┌─────────┴─────────┐
                    │                   │
               Local network       Remote network
                    │                   │
                    ▼                   ▼
              ARP resolution       Routing decision
                    │                   │
                    ▼                   ▼
               MAC address        Default gateway MAC
                    │                   │
                    └─────────┬─────────┘
                              ▼
                       ETHERNET FRAME
                              │
                ┌─────────────┴─────────────┐
                │                           │
          Source MAC                  Destination MAC
                │                           │
                └─────────────┬─────────────┘
                              ▼
                           SWITCH
                              │
                        MAC TABLE
                              │
                         MAC → PORT
                              │
                              ▼

```

The single most important distinction is:

> **IP addresses are used for Layer 3 logical addressing and routing; MAC addresses are used for Layer 2 delivery on the local network/link.**

And when communicating with a remote network:

```text
Destination IP = Remote host
Destination MAC = Next-hop device
```

That distinction becomes extremely important when you move into **ARP, VLANs, routing, packet analysis, MITM attacks, network enumeration, and penetration testing**.
