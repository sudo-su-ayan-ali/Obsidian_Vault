# 1. Windows User Enumeration — Detailed Guide

**User enumeration** in Windows privilege escalation means identifying **which user accounts exist, which account you are currently using, what groups they belong to, what privileges those groups provide, and whether any account information can help you escalate privileges**.

A useful mental model is:

> **Who am I? → Who else exists? → What groups exist? → Who belongs to privileged groups? → What security identifiers and account properties are associated with them?**

---

## 1. Current User Enumeration

### What it means

The **current user** is the account under which your command shell or process is currently running.

This should usually be your **first enumeration step** because every subsequent privilege-escalation decision depends on knowing your current identity.

### Command

```cmd
whoami
```

Example:

```text
C:\> whoami
thm-pc1\student
```

This tells you:

```text
Computer/Domain : THM-PC1
Username        : student
```

---

### Get detailed information

```cmd
whoami /all
```

This is extremely important for Windows privilege escalation.

It can show:

- Username
    
- SID
    
- Groups
    
- Group SIDs
    
- Privileges
    
- Integrity level
    
- Authentication information
    

Example:

```text
USER INFORMATION
----------------

User Name      SID
============== =============================================
thm-pc1\student S-1-5-21-...-1001
```

You may also see:

```text
GROUP INFORMATION
-----------------

Group Name                     Type
=============================  =================
Everyone                      Well-known group
BUILTIN\Users                 Alias
NT AUTHORITY\INTERACTIVE      Well-known group
```

And:

```text
PRIVILEGES INFORMATION
----------------------

SeChangeNotifyPrivilege
SeShutdownPrivilege
SeIncreaseWorkingSetPrivilege
```

### Why it matters

Suppose:

```text
whoami
```

returns:

```text
nt authority\local service
```

That is very different from:

```text
administrator
```

Likewise, a normal user possessing a powerful Windows privilege such as:

```text
SeImpersonatePrivilege
```

can be much more interesting from a privilege-escalation perspective than an ordinary user with only standard privileges.

---

## 2. Local User Enumeration

### What it means

A **local user** is an account created on the Windows machine itself.

For example:

```text
Administrator
Guest
student
backup
service
```

These accounts are stored in the local Security Account Manager (**SAM**) database.

### Basic command

```cmd
net user
```

Example:

```text
C:\> net user

User accounts for \\THM-PC1

-------------------------------------------------------------------------------
Administrator
Guest
student
backup
The command completed successfully.
```

This tells you which local accounts exist.

---

### Enumerate one particular user

```cmd
net user student
```

Example:

```text
User name                    student
Full Name                    Student User
Account active               Yes
Account expires              Never
Password last set            9/1/2026
Password expires             Never
Local Group Memberships      *Users
```

Important information includes:

|Field|Why it matters|
|---|---|
|User name|Account identity|
|Full Name|May reveal role/person|
|Account active|Determines whether account is usable|
|Password expires|Useful for account assessment|
|Last logon|Can indicate activity|
|Local Group Memberships|Shows privileges|
|Password required|Important security property|
|Account expires|Account lifecycle|

---

### PowerShell alternative

```powershell
Get-LocalUser
```

Example:

```text
Name          Enabled
----          -------
Administrator True
Guest         False
student       True
```

For one account:

```powershell
Get-LocalUser student
```

---

### Why local-user enumeration matters

Suppose you find:

```text
backup
service
developer
admin
```

The names themselves don't give you privileges, but they provide **context**.

For example:

```text
backup
```

may indicate a service account.

Then you can investigate:

- What services use that account?
    
- What groups does it belong to?
    
- Does it have special privileges?
    
- Are there scheduled tasks associated with it?
    

The important point is:

> **Finding an account is not the same as compromising an account.**

Enumeration establishes the attack surface; further authorized testing determines whether that account creates a security weakness.

---

# 3. Logged-in User Enumeration

This is slightly different from **current-user enumeration**.

### Current user

```cmd
whoami
```

answers:

> Which account is **my current process** running as?

### Logged-in users

You want to know:

> Which users currently have sessions on this Windows system?

---

## `query user`

```cmd
query user
```

Example:

```text
USERNAME      SESSIONNAME     ID  STATE   IDLE TIME  LOGON TIME
student       console          1  Active      none    9/26/2026
administrator rdp-tcp#2        2  Active      10:12   9/26/2026
```

This can reveal:

- Username
    
- Session ID
    
- Session type
    
- Active/inactive state
    
- Logon time
    

---

## `quser`

Equivalent commonly used command:

```cmd
quser
```

---

## `query session`

```cmd
query session
```

This focuses more on sessions.

---

## `qwinsta`

```cmd
qwinsta
```

Example:

```text
SESSIONNAME       USERNAME        ID  STATE
console           student          1  Active
rdp-tcp#1         administrator    2  Active
```

---

## Why logged-in users matter

Imagine:

```text
whoami
```

returns:

```text
THM-PC1\student
```

but:

```text
query user
```

shows:

```text
administrator
```

is currently logged in.

That tells you something important about the machine's current state.

However, **simply seeing Administrator logged in does not mean you can access their session**.

The enumeration tells you:

```text
Student → current identity
Administrator → another active session
```

That can be useful during authorized lab assessment because session information can influence your investigation of processes, services, credentials, and privilege boundaries.

# 4. Domain User Enumeration

This becomes important when the Windows machine is joined to an **Active Directory domain**.

For example:

```text
Domain: CORP.LOCAL
```

A domain can contain users such as:

```text
Administrator
j.smith
alice
bob
svc-backup
helpdesk
```

These accounts are managed by Active Directory rather than simply by the local machine.

---

## Determine domain information

```cmd
whoami
```

might return:

```text
corp\student
```

You can also use:

```cmd
echo %USERDOMAIN%
```

and:

```cmd
echo %USERDNSDOMAIN%
```

Example:

```text
CORP
CORP.LOCAL
```

---

## Enumerate domain users

A traditional command is:

```cmd
net user /domain
```

Example:

```text
C:\> net user /domain

User accounts for \\DC01

-------------------------------------------------------------------------------
Administrator
alice
bob
svc_backup
helpdesk
student
```

Notice the difference:

```cmd
net user
```

→ local users

```cmd
net user /domain
```

→ domain users

This distinction is **very important**.

---

## Query a specific domain user

```cmd
net user alice /domain
```

You might see:

```text
User name                    alice
Full Name                    Alice Smith
Global Group memberships     *Domain Users
                             *Developers
Account active               Yes
Password last set            ...
```

This can reveal the user's group memberships and account properties.

---

## PowerShell / Active Directory module

If the AD module is installed:

```powershell
Get-ADUser -Filter *
```

Specific user:

```powershell
Get-ADUser alice -Properties *
```

Useful properties include:

```powershell
Get-ADUser alice -Properties MemberOf,Description,Enabled,LastLogonDate
```

---

# 5. User Group Enumeration

Groups are one of the **most important concepts in Windows privilege escalation**.

Instead of assigning every permission individually to every user, Windows commonly uses groups.

For example:

```text
student
   |
   └── Users
```

or:

```text
administrator
   |
   └── Administrators
```

---

## Current user's groups

```cmd
whoami /groups
```

Example:

```text
GROUP INFORMATION
-----------------

Group Name                         Type
---------------------------------  -----------
Everyone                           Well-known
BUILTIN\Users                      Alias
NT AUTHORITY\INTERACTIVE           Well-known
NT AUTHORITY\Authenticated Users   Well-known
```

This tells you **which security groups your current token contains**.

---

## Local groups

```cmd
net localgroup
```

Example:

```text
Aliases for \\THM-PC1

-------------------------------------------------------------------------------
*Administrators
*Backup Operators
*Guests
*Users
*Remote Desktop Users
```

Then investigate a particular group:

```cmd
net localgroup administrators
```

Example:

```text
Members

-------------------------------------------------------------------------------
Administrator
student
```

If your account appears there:

```text
student
```

then:

```text
student → Administrators
```

That is a major privilege finding.

---

## PowerShell

```powershell
Get-LocalGroup
```

Members:

```powershell
Get-LocalGroupMember Administrators
```

Example:

```text
ObjectClass Name
----------- ----
User        THM-PC1\Administrator
User        THM-PC1\student
```

---

# 6. Privileged Group Enumeration

This is where enumeration becomes especially relevant to privilege escalation.

Windows has several groups with elevated capabilities.

The most obvious is:

```text
Administrators
```

But there are others.

Examples include:

```text
Administrators
Backup Operators
Remote Desktop Users
Remote Management Users
Power Users
Server Operators
Print Operators
Account Operators
```

**The exact privileges and applicability depend on Windows version and configuration.**

---

## Check Administrators

```cmd
net localgroup administrators
```

Example:

```text
Members
-------------------------------------------------------------------------------
Administrator
student
```

You can then map:

```text
student
   ↓
Administrators
   ↓
Administrative privileges
```

---

## Backup Operators

```cmd
net localgroup "Backup Operators"
```

Backup-related privileges can have significant security implications because backup functionality can allow access to protected data under appropriate configurations.

---

## Remote Desktop Users

```cmd
net localgroup "Remote Desktop Users"
```

Membership generally indicates that the account is authorized for RDP logon, subject to other policy/configuration requirements.

This isn't automatically equivalent to administrator privileges.

---

## Remote Management Users

```cmd
net localgroup "Remote Management Users"
```

This is relevant when investigating PowerShell remoting / WinRM access.

Again:

> **Group membership ≠ automatic administrator privileges.**

You need to understand what permissions the group actually grants on that particular system.

---

# 7. Domain Group Enumeration

In an Active Directory environment, groups can exist at the **domain level**.

For example:

```text
Domain Admins
Domain Users
Enterprise Admins
Schema Admins
Account Operators
Backup Operators
Help Desk
Developers
IT
```

---

## Enumerate domain groups

```cmd
net group /domain
```

Example:

```text
*Domain Admins
*Domain Users
*Enterprise Admins
*Help Desk
*Developers
*IT
```

---

## Inspect a domain group

```cmd
net group "Domain Admins" /domain
```

Example:

```text
Members

-------------------------------------------------------------------------------
Administrator
alice
```

This answers:

> Which users are members of Domain Admins?

---

## PowerShell

With the AD module:

```powershell
Get-ADGroup -Filter *
```

Specific group:

```powershell
Get-ADGroupMember "Domain Admins"
```

Example:

```text
Administrator
alice
```

---

## Why this matters

Consider:

```text
Current user:
student
```

Then:

```text
student → Domain Users
```

That's ordinary.

But if:

```text
student → Developers
```

you need to investigate what Developers can access.

Or:

```text
student → Backup Operators
```

you investigate the associated privileges.

And if:

```text
student → Domain Admins
```

the account has extremely broad domain-level administrative authority.

# 8. Account Information Enumeration

This goes beyond simply discovering usernames.

You want to understand **how an account is configured**.

Useful command:

```cmd
net user username
```

For example:

```cmd
net user student
```

Possible output:

```text
User name                    student
Full Name                    Student
Comment
User's comment
Country/region code          000
Account active               Yes
Account expires              Never
Password last set            9/20/2026
Password expires             Never
Password changeable          9/20/2026
Password required            Yes
User may change password     Yes
Workstations allowed         All
Logon hours allowed          All
Local Group Memberships      *Users
Global Group memberships     *Domain Users
```

---

## Important fields

### Account active

```text
Account active Yes
```

means the account is enabled.

---

### Account expires

```text
Account expires Never
```

means there is no configured expiration date.

---

### Password last set

```text
Password last set 9/20/2026
```

Useful for understanding account lifecycle.

---

### Password required

```text
Password required Yes
```

Indicates whether a password is required under the account configuration.

---

### Group membership

This is often the most security-relevant part:

```text
Local Group Memberships
*Users

Global Group memberships
*Domain Users
*Developers
```

Now you can follow the privilege chain.

# 9. User SID Enumeration

## What is a SID?

**SID = Security Identifier**

Windows doesn't fundamentally identify security principals by the username string.

Instead, Windows uses a unique SID.

Example:

```text
S-1-5-21-3623811015-3361044348-30300820-1013
```

A local Administrator might have:

```text
S-1-5-21-...-500
```

A normal local user might have:

```text
S-1-5-21-...-1001
```

---

## Find your SID

```cmd
whoami /user
```

Example:

```text
USER INFORMATION
----------------

User Name          SID
================== ============================================
thm-pc1\student    S-1-5-21-123456789-987654321-111111111-1001
```

---

## Using `wmic`

On systems where WMIC is available:

```cmd
wmic useraccount get name,sid
```

Example:

```text
Name          SID
Administrator S-1-5-21-...-500
Guest         S-1-5-21-...-501
student       S-1-5-21-...-1001
```

Newer Windows versions may not have WMIC enabled, so don't rely on it exclusively.

---

## PowerShell

```powershell
Get-LocalUser | Select-Object Name,SID
```

Example:

```text
Name          SID
----          ---
Administrator S-1-5-21-...-500
Guest         S-1-5-21-...-501
student       S-1-5-21-...-1001
```

---

# Understanding the SID Structure

A SID can look like:

```text
S-1-5-21-123456789-987654321-111111111-1001
```

Conceptually:

```text
S
│
├── 1
│   Revision
│
├── 5
│   Identifier Authority
│
├── 21
│   Machine/domain identifier
│
└── 1001
    Relative Identifier (RID)
```

The final number is particularly interesting.

For common built-in local accounts:

```text
Administrator → RID 500
Guest         → RID 501
```

A normal user may have a RID such as:

```text
1001
1002
1003
```

So:

```text
S-1-5-21-AAA-BBB-CCC-500
                         ↑
                        RID
```

The RID helps identify the account within that security domain.

# Putting Everything Together

For Windows privilege escalation, don't treat these commands as isolated facts.

Build an **identity → group → privilege → access** chain.

For example:

```text
Current User
     │
     ▼
student
     │
     ├── SID
     │
     ├── Groups
     │      │
     │      ├── Users
     │      └── Backup Operators
     │
     └── Privileges
            │
            ├── SeChangeNotifyPrivilege
            └── ...
```

Then investigate the environment around those findings.

# Practical Enumeration Workflow

When you get a Windows shell, a useful initial sequence is:

### 1. Who am I?

```cmd
whoami
```

### 2. Get complete identity information

```cmd
whoami /all
```

### 3. Get SID

```cmd
whoami /user
```

### 4. Get groups

```cmd
whoami /groups
```

### 5. Enumerate local users

```cmd
net user
```

### 6. Inspect interesting users

```cmd
net user username
```

### 7. Enumerate local groups

```cmd
net localgroup
```

### 8. Inspect Administrators

```cmd
net localgroup administrators
```

### 9. Check logged-in users

```cmd
query user
```

### 10. Determine domain

```cmd
echo %USERDOMAIN%
echo %USERDNSDOMAIN%
```

### 11. Enumerate domain users

```cmd
net user /domain
```

### 12. Enumerate domain groups

```cmd

```

### 13. Inspect important domain groups

```cmd

```

# What You Should Actually Look For

When doing a **Windows privilege-escalation assessment**, don't simply collect a list of usernames.

Look for relationships such as:

```text
Who am I?
    ↓
What groups am I in?
    ↓
Are any groups privileged?
    ↓
What privileges does my token have?
    ↓
What other users exist?
    ↓
Which users are privileged?
    ↓
Who is currently logged in?
    ↓
What services/tasks/processes belong to those accounts?
```

The important transition is:

> **Enumeration → relationship mapping → privilege analysis**

For example:

```text
student
   │
   ├── Member of: Users
   │
   ├── Member of: Backup Operators
   │
   └── Privilege: SeBackupPrivilege
                         │
                         ▼
                Investigate backup-related
                authorization boundaries
```

That is much more valuable than simply knowing that a user named `backup` exists.

### Recommended learning order

For your Windows privilege-escalation notes, I'd structure **User Enumeration** as:

```text
1. Current User Enumeration
   ├── whoami
   ├── whoami /user
   ├── whoami /groups
   └── whoami /priv
       
2. Local User Enumeration
   ├── net user
   ├── net user <username>
   └── Get-LocalUser

3. Logged-in User Enumeration
   ├── query user
   ├── quser
   ├── query session
   └── qwinsta

4. Domain User Enumeration
   ├── Domain identification
   ├── net user /domain
   ├── net user <user> /domain
   └── Get-ADUser

5. User Group Enumeration
   ├── whoami /groups
   ├── net localgroup
   └── Get-LocalGroupMember

6. Privileged Group Enumeration
   ├── Administrators
   ├── Backup Operators
   ├── Remote Management Users
   ├── Server Operators
   └── other privileged groups

7. Domain Group Enumeration
   ├── net group /domain
   ├── Domain Admins
   ├── Enterprise Admins
   └── Get-ADGroupMember

8. Account Information
   ├── Account status
   ├── Password settings
   ├── Logon information
   ├── Group membership
   └── Account restrictions

9. SID Enumeration
   ├── SID structure
   ├── Domain SID
   ├── User SID
   ├── RID
   └── Well-known SIDs
```

The **next logical section** after this is **Windows Privilege Enumeration**, especially `whoami /priv`, integrity levels, UAC, Windows privileges such as `SeImpersonatePrivilege`, `SeBackupPrivilege`, `SeRestorePrivilege`, `SeDebugPrivilege`, and how to determine which ones actually create privilege-escalation opportunities.
